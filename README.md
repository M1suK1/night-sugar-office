# 夜糖事务所

黑色、雾白与蔷薇粉的魔法少女经营游戏前端原型。以原创等距夜城地图为核心，包含九片地形辖区与环境影响、分三批放号的限时委托、20:00–次日 02:00 跨午夜夜班与打烊交接、可随时唤起的 CMD 终端、剪影立绘与四格衣柜、战斗与调查两类派遣、自动战斗回放、七阶关系、疤痕与退役、契约经济、市场四标签、自定义契约者、装备与势力物资、侵蚀/魔女化、城市安定度与周期 Boss，以及可折叠的叙事引擎控制台与 SillyTavern 对话补全预设。

本版立绘统一使用分层剪影占位，仅用于验证服装、表情、导入 PNG 与头像联动等功能；完整分层美术将在后续替换，不影响现有数据结构与交互。

**仅前端，没有自建后端。** 故事引擎可选地由浏览器直连任意 OpenAI 兼容接口；不配置时，剧情由本地关键词/脚本响应演示，界面有明确标识。没有账号、支付或云端存储。

## 运行

建议 Node.js 22.18+ 或 24+，使用 npm。

```sh
npm ci
npm run dev -- --port 5173 --strictPort
```

打开终端打印的本地地址。生产预览：

```sh
npm run build
npm run preview -- --port 5173 --strictPort
```

浏览器不能通过双击 HTML 正确运行 Vite 的模块和绝对路径资产；请使用开发/静态预览服务。部署到域名根路径即可，不需要业务服务端。

## 可体验的内容

- **城市派遣**：地图/列表切换、战斗与调查分类筛选、缩放；悬停角色显示简报；拖动角色到任务点，或点击任务后编队；战斗最多 3 人、调查最多 2 人。低血量、疲劳、忙碌及重复派遣均有约束和内部提示。
- **九片辖区**：地图按 `city.svg` 的地形切成糖果公园、北岸桥头、月见台、玻璃温室、旧教堂、南十字、旧城区、旧钟楼与星见川码头；大小不一、边界贴合河流与街区。点选辖区可读区域背景，并查看该地委托的环境修正——调查目标、报酬、伤害、疲劳、精神与敌方血量各有增减，结算与战斗都会实际读取。
- **批次委托与时限**：每晚 20:00、22:00、00:00 各放出一批委托；紧急委托两小时内必须接下，否则自动撤销，长期委托整晚有效、打烊时统一清场。地图上会标出截止时间，过期的信号以灰色「已消散」保留到当晚结束。
- **自动战斗**：每 15 分钟一轮，洞察值随机波动决定行动顺序，技能按权重释放并判定命中；全自动、玩家不可干预。战斗以全屏剧场回放，支持播放、暂停、倍速、跳过与完整战报。胜利移除事件；时间耗尽为暂时击退，获得八成收益，魔物带伤回到池中；失败保留事件并留下疤痕。战报与记录页都能进入「战斗札记」：独立 `battle` 预设把已发生的回合扩写成 3–5 场多人叙事，中间正文、两侧立绘，台词按说话者切换表情与高亮；没有 API Key 或生成失败时改读本地战报简报，不改写任何战斗结果。
- **人物档案**：状态、能力、关系、契约成长、外观装备、心愿六页；血量、共情值、疲劳、侵蚀度、五格疤痕、三技能与七阶关系。契约成长页显示当前目标、随机显露的特性、经验与升级进度、契约期限、退休金和欠缴。外观页提供四格衣柜预览、六种表情、装备栏与右侧仓库抽屉；装备可从仓库拖入法器/护符槽，侵蚀度在状态概览疲劳值下方。自定义登记的魔法少女会直接把服装描述与立绘占为第一格「契约礼装」，不再浮在衣柜之外。
- **表情差分导入**：外观页的六种表情可逐个导入图片，也可一次多选按文件名（如 `yue-calm.png`、`yue-smile.png`）自动识别；每套服装独立保存，最多六张，魔女化立绘也有自己的独立表情页。导入后角色档案、对话、战斗札记与多人舞台都会真的换成对应图片，未导入的表情继续使用基础立绘或程序化表情；移除差分即回到基础立绘，不会伪造不存在的表情。自定义登记还能导入 JSON「衣柜包」，一次带入多套服装、各套表情差分与魔女化立绘。
- **衣柜导入**：人物详情的外观页提供「导入衣柜」。可一次导入 JSON（`outfits`/`wardrobe` 数组、整张契约卡或纯文本粘贴）、多张图片（自动裁成 768×960 WebP 立绘），或直接复制另一位契约者的服装；合并或替换模式、四格上限与超出提示都会即时显示。
- **跨午夜六小时夜班**：营业时间为 20:00–次日 02:00，00:00 之后仍算同一夜，日结只在打烊时发生。手动推进 30 分钟、自动推进 5 分钟都受打烊时间约束；点「前往下一天」会先弹出二次确认，结算当晚委托与疲劳恢复后进入次日 20:00。
- **侵蚀与魔女化**：战斗、Boss 与高疲劳会积累侵蚀；三阶段分别降低共情、提高其余属性。第三阶段成为魔女，需要每 10 日使用一次月蚀抑制剂；断药期最长 10 日，期间禁止派遣与远行，第 10 日死亡。
- **市场四标签**：候选名册、在册契约、势力物资、退休区。市场等级决定每日候选人数，可花星砂升级；高级招募可指定 1–6 级，但会消耗城市安定度。势力物资每天为每个势力刷新三个货位，可重复出现同一物品，但每个货位只能购买一次；售罄状态与次日刷新都记录在存档中。
- **自定义契约者**：五步登记向导，自由分配 260 点能力、选择三技能与三特性、挑选代表色、导入并裁剪 PNG 立绘；可在最后一步导入衣柜包，一次带入最多四套服装、按服装保存的表情差分和魔女化立绘。导入立绘后可由故事引擎读取画面补全身世与外貌，职阶会决定 260 点的自动分配；固定 1 级，登记后进入候选名册。
- **契约卡导出**：人物档案可把当前角色导出为本地 JSON 卡片，包含立绘、三技能、特性、关系、疤痕、装备与契约数据。市场「导入卡片」可在新存档重新登记，保留原始数值但不继承退役状态；卡片指纹避免重复导入，数据不完整时拒绝。
- **基地二级菜单**：点击会客厅、诊所、宿舍、星象台打开房间详情，不跳页。会客厅包含议事、成员、物资、势力代表四页；诊所按缺失血量收费并按小时治疗，宿舍负责恢复疲劳；星象台可派两人远行。
- **契约经济**：雇佣有期限，到期需续签；退休金按等级每日计提，退役成员会持续占用事务所预算。欠缴过久会强制退役。月光诊所统一为「治疗」：按缺失血量收费、半小时一档向上取整、按小时线性回血，期间不能派遣、不恢复疲劳（疲劳归宿舍）；「治疗癖好」是独立的 2 小时护理，不回血、单独收费，只提升羁绊并小幅增加侵蚀；重塑、抑制、宿舍都按「一人一格」的卡片展示。记忆重塑与复制契约保留，价格与限制写在按钮上。
- **会客厅与星象台**：基地会客厅可以批准、暂缓或驳回成员议题，也可任命值班助理；每个选项会提前列出星砂、时间、装备、势力态度、安定度或契约者代价，资源不足时锁定并说明还差多少。暂缓只扣提出者羁绊与所属势力态度，并保证下个议事日重新提出；驳回在关系代价之外按主题扣资源。提出者会先播放一段逐句推进的对白，点击「继续」或按空格推进，对白结束后才显示选项。星象台可派两人远行，按小时结算，疲劳过高会自动返程。
- **退休区**：退役成员进入市场页的退休区，可返聘、查看退休金状态，并通过手机远程联络；每次通话消耗星砂，每日首次提升羁绊。
- **代价与纪念**：疤痕降低血量上限并附带精神或肉体后遗症；第五道疤痕导致死亡，角色移入星光纪念墙。累计四道疤痕可申请退役转任文职。
- **CMD 终端**：顶栏 `CMD` 按钮或 `Ctrl+K` 唤起底部终端，支持 `help`、`status`、`advance 30`、`end`、`page base`、`generate`、`preset use <名称>`、`district candy`、`mission <关键词>`、`girl <名字>` 与 `clear`；↑↓ 翻历史，Esc 关闭。终端只是入口，打烊仍然要二次确认。
- **叙事引擎控制台**：连接测试、提案生成、角色起草与每句对话都会记入右下角可折叠、可拖动左上角调整宽高的「叙事引擎」面板（尺寸会记住）。展开一条记录，能看到成功/失败、HTTP 状态与耗时，以及本次实际发出的分段内容（世界观、预设、记忆、历史、玩家输入）、采样参数、模型思维链与 token 用量；可按失败筛选、复制或清空，密钥不会写入日志。被 `finish_reason: length` 截断时会自动把最大 token 放大到 3200 重试一次，仍失败则提示去预设里调高上限。
- **对话补全预设**：设置 → 故事引擎 →「对话补全预设」，可导入 SillyTavern 的对话补全预设 JSON（`temp_openai`、`top_p_openai`、`openai_max_tokens`、`main`、`jailbreak` 等），把采样参数与系统提示注入请求；支持 `prompt_order` 顺序、ST 宏、正则脚本（输入/输出、仅提示词/仅显示，带双端预览）、`scenario_format` / `personality_format` / `wi_format` 格式串，以及每个预设自己的接口与密钥（导出带 schema 4 与词条用途、剥除密钥）。词条按用途分成共用、角色对话、每日提案、角色起草、故事线、私人事件、完整剧情、突发事件、服装词条与战斗札记；每个请求只注入共用词条和本任务词条，代码里的 JSON 输出契约永远排在最后。设置页为十种用途各留一个入口，入口若当前绑定的是只读内置预设，会先复制成可编辑副本并改绑；预设编辑器按任务分十一个标签页（共用、九个生成任务、全部词条），任务页只显示并改绑该任务的预设，共用/全部页保留预设列表与编辑对象下拉，并可改用途、恢复本用途默认；首次升级会把九个任务的默认预设拆成以任务命名的独立副本（如「每日提案」「完整剧情」「战斗札记」），旧「… 副本」默认副本会原地接管改名而不是再复制一份；导入缺少任务词条的 ST 预设时会自动补齐并标记为默认。兼容 SillyTavern 的平铺键名（`temperature` / `top_p` / `max_tokens`）与 `prompt_order` 顺序，导入时会列出被忽略的扩展（SPreset、Tavern Helper、工具调用词条）；九个生成任务（角色对话、每日提案、角色起草、故事线、私人事件、完整剧情、突发事件、服装词条、战斗札记）各自绑定预设，并各有一份以任务命名的可编辑默认预设，旧版三条链路绑定会自动拆开迁移；剧情请求会把 `scenario_format` / `personality_format` 应用到场景与角色性格块，预设词条若未引用 `{{scenario}}` / `{{personality}}`，会自动补一段【场景】【角色性格】；每套预设还能单独填 Endpoint / 模型 / 密钥（三项齐全才生效，导出时剥掉密钥），并支持 ST 的 `regex_scripts`：按 placement 区分输入/输出、按 destination 区分发给模型的 prompt 与界面显示的文本。内置「平衡 / 严格 JSON / 克制语气」三套，也可导出回 ST 格式。未支持的字段会在导入报告中列出。旧版设置里的世界观/每日要求会迁移成一份可编辑预设；旧每日要求若还写着「不要给任何数值、奖励或规则」，词条下方会标出冲突并提供一键移除。
- **灯下私语**：自由输入、快捷话题、角色立绘、聊天历史、羁绊和场景记忆面板。配置叙事者后，模型会结合角色完整设定、关系网络、战斗经历与全部对话历史生成台词；失败时回退本地剧情。每条输入最多 500 字，每位角色保留最近 60 条消息，日羁绊增长有限制。
- **基地**：会客厅、月光诊所、晚安宿舍、星象台平面图；显示在场成员与位置；房间详情、交谈和扩建。扩建宿舍增加契约席位，其他设施扩建提升空间容量。
- **市场**：候选契约者筛选、搜索、完整档案及签约确认；资金和基地容量联动。退役成员保留在退休区，可远程联络或返聘。
- **城市危机**：第 16 日首次出现周期 Boss；Boss 在场时每 3 小时降低 1 点城市安定度，48 小时未处理额外扣 6 点。安定度影响雇佣折扣、每日委托数量与编队契合。
- **记录**：收入、支出、声望折线图；时间范围、键盘可访问的数据点、日志分类、战斗档案与分页。跨午夜结算按行动的实际完成时刻归日。
- **编年史缓存**：生成或登记的魔物、少女、委托、议程与势力代表会写入独立编年史；即使内容从池中移除或委托完成，仍可在记录页按类别回看。缓存上限 200 条，随存档保存。
- **夜班提案 v2**：故事引擎现在会一次生成完整提案——魔物血量、属性、技能与规则，候选者的等级、四维、技能与特性，委托的时长、报酬、判定、目标、轮数与额外装备，议会提案的逐句对白与三个带资源代价的选项，使者委托，以及最多两件一次性装备。提案先经本地校验（枚举、引用、预算、驳回必须带实际惩罚、暂缓只能扣羁绊与势力），硬错误会带着错误清单让模型修复一次；修不好就中止且不写入。手动生成会先打开完整预览，确认「采纳」后才落库；每日自动补充先检查三池容量，干净提案直接应用，被裁剪的提案附带警告。装备随存档保留并重新登记到物品表。
- **魔物图鉴**：六种魔物的几何剪影、属性、技能、习性与弱点；可从侧栏或战斗编队直接打开。
- **内容工坊**：底部工具条的「内容工坊」可人工设计技能、装备与消耗品、魔物、委托、弹窗事件，不写代码也能造内容。六页签共用「列表 → 表单 → 预览」布局，调查委托与战斗委托分成两个独立页签与模板：技能可编排最多 6 条附加效果，效果可从按「进攻 / 防护 / 速度 / 精神 / 控制 / 续航」分类的 20 个状态模板中筛选并下拉选择，也可切回自定义并手调数值；装备可设阵营、槽位、价格、声望要求、伤害与先手加成、附带技能与消耗品效果；魔物可调阶级、属性、程序化立绘参数、习性与弱点，并用 **MonsterRule** 组合「每轮开始 / 命中 / 常驻」×「再生、增益、加速、减益攻击者、持续伤害、免疫眩晕、伤害减免」等战斗特性，魔物技能按阶级筛选；调查委托可设判定属性与目标值，战斗委托可设 1–3 只敌人与轮数，敌人按等级筛选，两者共用标题、分类、难度、时长、推荐等级、辖区、接取窗口、报酬与颜色，并可在星砂之外附赠一件装备或一名指定等级的免费契约者，完成后装备进背包、契约者免签约金入职（宿舍满员则留在候选名册），也能「投放测试」立刻在当前夜晚生成一份；弹窗事件可设标题、正文、类型、势力、辖区、绑定契约者、2–3 个选项与各自的星砂/声望/势力/契约者/辖区效果，以及触发方式、权重与每日一次；触发方式为「随机池」的卡会在每日开门时按权重抽取（池越大越容易触发，待处理事件满 3 张时不再抽取），「投放测试」会立刻弹出并快照进当前存档。内置条目只读，可「复制为自制」；自制条目独立存在 `night-sugar:content:v1` 内容库，保存后立即进入图鉴、商店货架、夜间委托轮转池、蓝图「阶段委托」模板与「强制弹窗」事件库、战斗池，刷新后仍在。删除前会检查存档引用，其中被故事蓝图引用的弹窗卡也会被拦下。整座内容库可导出为 `night-sugar/content-library` JSON 内容包，导入时可选「冲突另存 / 冲突覆盖 / 冲突跳过」，并显示新增、覆盖、改名、跳过与非法条目的数量；导出 → 清空 → 导入可完整恢复。
- **辅助功能**：内部通知、设置、操作手册、减少动画、存档导出与导入、覆盖确认、双重确认重置；每 12 秒自动推进 5 分钟或手动推进 30 分钟。存档导入会先校验版本、角色与核心字段，损坏文件不会覆盖当前进度。

- **会客厅（独立页面）**：议会在侧栏单独成页。左侧是提案者的状态与特性，中间是无背景框、等比放大的主立绘、议题与三个选项（可按 1 / 2 / 3 选择），右侧是值班助理；进入议题时先播放提出者 3–4 句逐段对白，点击「继续」、按空格或直接跳过，对白结束后才显示决议。对白每一行可带表情，当前会驱动立绘表情，后续可扩展为整套立绘变化。决议通过时会客厅背景与下一位议员衔接，接受带辖区条款的决议会真的改变地图归属。选项会预览资源代价，资源不足的按钮置灰；暂缓会保留到下个议事日，驳回会同时结算关系与主题资源惩罚。
- **强制事件**：开门前后、势力施压、环境异变或契约者状态越线时，会弹出一张不能跳过的决策卡；处理完才能继续推进时间或打烊。接入模型时每天还会额外生成一条带三个选项的事件。
- **故事线委托与角色事件**：详情页可以为每位契约者起草四幕故事线（需要羁绊 20）。每一幕会先发布一份「故事委托」——标题、明确目标、辖区与难度都由叙事者给出；完成它才会触发该幕的剧情事件，事件收尾后才推进下一幕。故事委托不会被打烊清理，也不能从委托池里删掉。叙事者还能在委托里塞进专属魔物、要求某位少女先缔结契约并同行、完成后发专属装备，并接一个强制事件或额外角色事件。角色事件从详情页进入，未读时头像带角标。
- **空白档案**：开局可选「标准开局」或「空白档案」——后者只有 6000 星砂与一间会客厅，安定度为 0，第一次登记不受声望门槛限制。也可以直接双击 `start.cmd`（开发）或 `start-prod.cmd`（构建后本地预览）。
- **魔女化立绘**：侵蚀达到 40 后，衣柜第五格会解锁「魔女化 · 夜之形」；它可以单独保存立绘、配色与六种表情差分，不挤占四格礼装，也不会自动替换当前服装。
- **故事蓝图**：详情页的「蓝图编辑」把故事线展开成节点图——场景、选项、阶段委托、强制弹窗、议会提案、角色事件、奖励、等待与结束；拖动节点、从端口拖线连到目标节点（Ctrl+C / Ctrl+V 可复制粘贴节点），支持滚轮缩放、右键平移、框选多选、适应窗口、自动整理、试跑与幕概览；阶段委托可直接套用现有委托模板，并分「成功 / 失败」两个出口；强制弹窗可从内容工坊的事件库导入，选中后标题、正文、类型、势力与辖区会同步，运行时按弹窗卡结算，卡被删除则退回手填内容；奖励可给星砂、装备、技能、特性、属性成长与临时增益。保存后随契约卡导出，开场直接按图推进。
- **自定义特性与去背景**：自定义登记的特性改为手写（名称 / 描述 / 倾向），内置特性只作为填充模板；「只导入立绘」入口支持一句话画面要求（直接交给叙事者补全档案），入口与立绘步骤都提供按边缘连通的去背景（可调容差、可撤销原图）。

## 存档与演示边界

数据仅保存于当前浏览器、当前站点的 localStorage（`night-sugar-office:v1`）。刷新可恢复，清除站点数据会丢失；隐私模式/存储不可写时可继续游玩，但无法保证刷新后恢复。导出为 JSON 备份，也可从「设置 → 存档」导入并在二次确认后覆盖当前进度。损坏或关系不一致的本地存档自动回退到初始演示状态。

初始数据为第 14 日 20:00 开门，内置 7 项基础委托、首批 3 项时段委托（20:00 放号）、4 位在职角色、1 位退役角色、1 位候选角色、4 个房间和一条会客厅议题。夜间会继续在 22:00 与 00:00 各放出一批委托；未完成的紧急委托会过期，长期委托在打烊时统一清场。暂时击退或失败会回到事件池，并保留疤痕与疲劳。可在设置中重置体验。

战斗是确定性规则引擎：同一存档、同一编队、同一时间得到同一结果，模型无法改写战斗数值。每轮行动日志会展开命中与伤害的中间值，战斗结束后可回看完整剧场与战报。

## 代码结构与未来 LLM 扩展

- `src/game.ts` / `src/types.ts`：纯函数行动规则、状态模型、数据与恢复校验。
- `src/districts.ts`：九片辖区的地形多边形、背景文案与环境修正；`districtAt` 负责百分比坐标到辖区的落点判定。
- `src/shift.ts`：20:00–次日 02:00 营业时段、跨午夜判定、批次放号、紧急/长期截止时间与打烊时间。
- `src/presets.ts`：SillyTavern 对话补全预设的导入/导出、采样参数裁剪、`prompt_order` 排序、ST 宏、正则脚本、每预设独立接口，以及十种用途的词条默认值、按 scope 拼装（共用 → 本任务 → 代码契约）、旧提示词迁移、每任务独立绑定、旧三档绑定迁移，以及首次升级时把任务默认预设按用途拆开并改名。
- `src/contracts.ts`：契约期限、退休金、欠缴、续签与返聘。
- `src/economy.ts`：市场等级、每日候选、高级招募、势力声望与物资价格。
- `src/items.ts`：装备、消耗品、月蚀抑制剂与装备技能。
- `src/factions.ts`：三大势力、货架、会客厅代表与每日任务。
- `src/progression.ts`：经验曲线、特性抽取、当前目标、侵蚀、值班助理与议题生成。
- `src/combat.ts`：确定性战斗引擎、命中与效果结算、疤痕与战后收益。
- `src/battleNote.ts`：战斗札记的角色选角、战斗摘要、回合覆盖与说话阵营校验、失败时的本地简报；不改战斗结果。
- `src/expressions.ts`：六种表情的标签与别名、差分键 `<outfitId>:<expression>`、图片数据清洗、每套服装六张上限、文件名识别与衣柜/魔女化服装视图；只负责表情差分的元数据。
- `src/wardrobeImport.ts`：自定义登记衣柜包的 JSON 读取、四套服装上限、活动服装立绘、孤立差分过滤与魔女化立绘规范化。
- `src/content/`：技能池、魔物模板、特性目录与种子内容包；`library.ts` 负责自制内容库的加载、清洗、注册与引用检查；未来可由生成式内容包替换。
- `src/llm.ts`：故事引擎连接、按用途拼装提示词、各生成器请求、硬错误修复重试与日志；提案的具体 schema、目录快照、校验和物化在 `src/llm-night.ts`。请求带 60 秒超时、一次瞬时错误重试与可配置上下文预算；每次调用记录请求分段、思维链与用量。
- `src/llm-night.ts`：NightProposalV2 类型、模型可用目录、结构化提示词、全量校验（含议会选项语义与预算裁剪）、确定性物化；不直接改 `GameState`。
- `src/App.tsx`：页面导航、弹窗编排、持久化、时段与打烊交接、自动补充与通知。
- `src/components/`：派遣沙盘与辖区面板、编队、战斗剧场与札记舞台、档案、衣柜与表情差分导入、叙事引擎控制台、对话预设、图鉴、纪念墙、剪影立绘、自定义向导、对话与辅助弹窗。
- `src/views/`：基地、市场、经营记录与市场四标签。
- `public/art/`：本地原创 SVG 城市；`public/fonts/`：本地子集字体。角色立绘当前由 `GirlPortrait` 渲染剪影，衣柜立绘或导入 PNG 则显示原图。
- `tests/`：120 项状态回归与 55 组真实浏览器交互验收。

## 故事引擎（可选）

设置 → 故事引擎可连接任意 OpenAI 兼容接口，并在浏览器内填写接口地址、模型与密钥。密钥、提示词与自动补充偏好只存于 localStorage，不写入游戏存档；刷新后保留，清除站点数据即删除。

- 「世界观与语气」「本次生成要求」可直接编辑，也可恢复默认。
- 每次连接测试、提案生成、角色起草与对话都会记入右下角可折叠的「叙事引擎」面板。展开条目可看成功/失败、HTTP 状态、耗时、本次读取的分段内容、采样参数、思维链与 token 用量；可按失败筛选、复制或清空；API 密钥不会写入日志。旧的「设置 → 日志」列表已并入该面板。
- 「生成今晚的提案」在本地校验后落地 1 只魔物、1 位候选者、1 条战斗委托、1 条代表委托与 1 份会客厅议题；属性、轮次与奖励由本地规则计算。生成请求会附带当前日期、星砂、安定度、待处理委托、Boss 与三方声望，让新内容接上现有局势。
- 所有模型请求均有 60 秒超时与一次瞬时错误重试；角色对话按 12,000 字符预算（可由绑定预设的 `openai_max_context` 覆盖）裁剪，优先保留系统设定与最近消息，超出部分会明确标注为省略。`4xx` 会直接展示服务端原文，便于判断密钥、模型名或请求格式问题。
- 生成的代表委托会直接挂到对应势力的会客厅代表名下；议题进入待议列表，可批准、暂缓或驳回。
- 自定义契约者在五步向导前提供「只导入立绘」入口：立绘会作为 `image_url` 发送给支持视觉的模型，用于补全身份、外貌与描述；每个字段标注「由使魔补全」并可单独重写，底部可重新生成全部。元素与职阶决定 260 点的自动分配，仍可手动调整；未点「登记并加入名册」前不会写入候选池。不支持视觉的模型会返回明确的接口错误，日志中保留状态码与服务端原文。
- 开启「每日自动补充」后，跨日且满足三池容量预检时自动请求一次，生成中不会重复触发；硬错误不落库，软裁剪会把警告写进通知。
- 设置 → 内容池可调整三池上限并手动移除条目；池满时生成按钮会停止。生成的事件、魔物与候选者都可以在内容池里单独删除。

浏览器直连会把密钥暴露给页面脚本，只适合本地原型验证；正式部署应改为服务端代理。模型文本不能直接修改资源、战斗结果或执行页面代码。


内容生成的设计边界记录在 `tasks/combat-plan.md`，第三版扩展记录在 `tasks/expansion-plan-3.md`，第四版市场/势力/侵蚀方案与实施说明记录在 `tasks/plan-v4.md`，第五版（九辖区、叙事引擎面板、ST 预设、四格衣柜、跨午夜夜班、批次限时委托、CMD 终端）记录在 `tasks/plan-v5.md`，第十版内容工坊方案记录在 `tasks/plan-v10.md`，第十一版夜班提案 v2 记录在 `tasks/plan-v11.md`：模型生成文案与机制，本地只做目录引用、预算、语义校验与确定性物化；模型永远不能直接修改状态，战斗结果始终由规则引擎结算。第十二版提示词按用途拆分的方案与验收记录在 `tasks/plan-v12.md`，第十三版每任务独立绑定与任务标签页记录在 `tasks/plan-v13.md`，第十四版战斗札记与敌方立绘通道记录在 `tasks/plan-v14.md`，第十五版表情差分导入记录在 `tasks/plan-v15.md`，第十六版魔女化表情页与自定义衣柜包记录在 `tasks/plan-v16.md`。
