# 夜糖事务所

黑色、雾白与蔷薇粉的魔法少女经营游戏前端原型。以原创等距夜城地图为核心，包含九片地形辖区与环境影响、分三批放号的限时委托、20:00–次日 02:00 跨午夜夜班与打烊交接、可随时唤起的 CMD 终端、剪影立绘与四格衣柜、战斗与调查两类派遣、自动战斗回放、七阶关系、疤痕与退役、契约经济、市场四标签、自定义契约者、装备与势力物资、侵蚀/魔女化、城市安定度与周期 Boss，以及可折叠的叙事引擎控制台与 SillyTavern 对话补全预设。

本版立绘统一使用分层剪影占位，仅用于验证服装、表情、导入 PNG 与头像联动等功能；完整分层美术将在后续替换，不影响现有数据结构与交互。

**仅前端，没有自建后端。** 故事引擎可选地由浏览器直连任意 OpenAI 兼容接口，或接上 Google Vertex AI（服务账号 JSON / Express 密钥）；不配置时，剧情由本地关键词/脚本响应演示，界面有明确标识。没有账号、支付或云端存储。

## 运行

建议 Node.js 22.18+ 或 24+，使用 npm。

```sh
npm ci
npm run dev -- --port 5173 --strictPort
```

打开终端打印的本地地址。生产预览：

```sh
npm run build
npm run preview -- --port 5173 --strictPort
```

浏览器不能通过双击 HTML 正确运行 Vite 的模块和绝对路径资产；请使用开发/静态预览服务。部署到域名根路径即可，不需要业务服务端。

`dev` / `build` / `preview` 都经由 `tools/vite.mjs` 启动，它把 esbuild 的临时目录固定到仓库内的 `.tmp/`。不这样做的话，esbuild 会往系统临时目录写中转文件再删除，在受限账户或沙箱里会报 `[vite:esbuild-transpile] remove C:\...\Temp\esbuild-...: Access is denied`。

## 可体验的内容

- **城市派遣**：地图/列表切换、战斗与调查分类筛选、缩放；悬停角色显示简报；拖动角色到任务点，或点击任务后编队；战斗最多 3 人、调查最多 2 人。低血量、疲劳、忙碌及重复派遣均有约束和内部提示。
- **九片辖区**：地图按 `city.svg` 的地形切成糖果公园、北岸桥头、月见台、玻璃温室、旧教堂、南十字、旧城区、旧钟楼与星见川码头；大小不一、边界贴合河流与街区。点选辖区可读区域背景，并查看该地委托的环境修正——调查目标、报酬、伤害、疲劳、精神与敌方血量各有增减，结算与战斗都会实际读取。
- **批次委托与时限**：每晚 20:00、22:00、00:00 各放出一批委托；紧急委托两小时内必须接下，否则自动撤销，长期委托整晚有效、打烊时统一清场。地图上会标出截止时间，过期的信号以灰色「已消散」保留到当晚结束。
- **辖区污染度**：九个辖区各有独立的污染度（0–100）与五档分级——清洁 / 微浊 / 浑浊 / 深染 / 灾厄，地图上以半透明色层与标签直接标出，右侧面板给出等级、每夜自然上升、完成委托后的净化预估与风险提示。污染只按自然规律上升，势力掌控只影响净化减免：委托生成时会把当时的污染与辖区归属冻结进委托，之后辖区易主或净化都不会回头改写已派出的委托。污染会同时提高敌方血量与攻击、压低报酬，并在深染以上带来额外疲劳与侵蚀。
- **三方势力与档案**：星灯协会、市役所、月蚀庭各有自己的会长 / 课长 / 领袖、理念、对城市与魔女的态度与内部裂痕，地图上的势力卡可直接打开档案（不再跳回基地）。档案分理念、成员、城市、魔女、关系五页，成员页列出隶属于该势力的少女；态度按声望分档，低于 30 即进入「戒备」。
- **出身标签与拦截战**：每位少女都带一枚出身标签（星灯协会 / 市役所 / 月蚀庭 / 无所属），与雇主「夜糖事务所」分开显示——事务所是中性机构，不参与辖区争夺，也不是第四方。派遣仍在「戒备」辖区里的普通委托时，会先被该势力所属的少女拦截：原委托被覆盖为拦截图，打赢声望 −4、打输 −2，原委托作废、队伍遣散；Boss、使者与故事线委托不受拦截。契约卡带着出身一起走：从别的存档导进来的少女保留卡片里写的那一方，不会在进市场时被重新分配；旧卡片没写这一项时按名字确定性补齐，同一张卡每次导入结果都一样。
- **事务所档案同步世界书**：基地页的「事务所档案」可编辑背景、理念与目标，并任命一位对外代表（羁绊 40 以上的在册少女）。保存后自动写入世界书里一条只读的「夜糖事务所」词条，附带对外代表的一句话；词条由档案派生，改内容要到档案里改。旧存档里的「月蚀教团」会就地更名为「月蚀庭」。
- **自动战斗**：每 15 分钟一轮，敏捷决定速度值（行动顺序），洞察决定命中，技能按权重释放；全自动、玩家不可干预。战斗以全屏剧场回放，支持播放、暂停、倍速、跳过与完整战报。胜利移除事件；时间耗尽为暂时击退，获得八成收益，魔物带伤回到池中；失败保留事件并留下疤痕。战报与记录页都能进入「战斗札记」：独立 `battle` 预设把已发生的回合扩写成 3–5 场多人叙事，中间正文、两侧立绘，台词按说话者切换表情与高亮；没有 API Key 或生成失败时改读本地战报简报，不改写任何战斗结果。
- **成长与提示**：升级默认发 10 点可分配属性（也可在设置里切回按职阶自动加主 6 / 副 4），每级最大生命 +10；档案「契约成长」页可逐点分配四维、名册显示 `+N` 角标。委托完成与角色升级都会进通知中心，并以排队提示逐条弹出，不会互相覆盖。
- **人物档案**：状态、能力、关系、契约成长、外观装备、心愿六页；血量、共情值、疲劳、侵蚀度、五格疤痕、三技能与七阶关系。契约成长页显示当前目标、随机显露的特性、经验与升级进度、契约期限、退休金和欠缴。外观页提供四格衣柜预览、六种表情、装备栏与右侧仓库抽屉；装备可从仓库拖入法器/护符槽，侵蚀度在状态概览疲劳值下方。自定义登记的魔法少女会直接把服装描述与立绘占为第一格「契约礼装」，不再浮在衣柜之外。
- **表情差分导入**：外观页的六种表情可逐个导入图片，也可一次多选按文件名（如 `yue-calm.png`、`yue-smile.png`）自动识别；每套服装独立保存，最多六张，魔女化立绘也有自己的独立表情页。导入后角色档案、对话、战斗札记与多人舞台都会真的换成对应图片，未导入的表情继续使用基础立绘或程序化表情；移除差分即回到基础立绘，不会伪造不存在的表情。自定义登记还能导入 JSON「衣柜包」，一次带入多套服装、各套表情差分与魔女化立绘。
- **衣柜导入**：人物详情的外观页提供「导入衣柜」。可一次导入 JSON（`outfits`/`wardrobe` 数组、整张契约卡或纯文本粘贴）、多张图片（自动裁成 768×960 WebP 立绘），或直接复制另一位契约者的服装；合并或替换模式、四格上限与超出提示都会即时显示。
- **跨午夜六小时夜班**：营业时间为 20:00–次日 02:00，00:00 之后仍算同一夜，日结只在打烊时发生。手动推进 30 分钟、自动推进 5 分钟都受打烊时间约束；点「前往下一天」会先弹出二次确认，结算当晚委托与疲劳恢复后进入次日 20:00。
- **侵蚀与魔女化**：战斗、Boss 与高疲劳会积累侵蚀；三阶段分别降低共情、提高其余属性。第三阶段成为魔女，需要每 10 日使用一次月蚀抑制剂；断药期最长 10 日，期间禁止派遣与远行，第 10 日死亡。
- **市场四标签**：候选名册、在册契约、势力物资、退休区。市场等级决定每日挂牌人数：1 级只摆 2 位，升到 2 / 3 / 4 级后依次 3 / 4 / 5 位，其余候选留在市场池里按日轮换，可花星砂升级；高级招募可指定 1–6 级，但会消耗城市安定度。势力物资每天为每个势力刷新三个货位，可重复出现同一物品，但每个货位只能购买一次；售罄状态与次日刷新都记录在存档中。
- **自定义契约者**：五步登记向导，自由分配 260 点能力、选择三技能与三特性、挑选代表色、导入并裁剪 PNG 立绘；可在最后一步导入衣柜包，一次带入最多四套服装、按服装保存的表情差分和魔女化立绘。导入立绘后可由故事引擎读取画面补全身世与外貌，职阶会决定 260 点的自动分配；固定 1 级，登记后进入候选名册。
- **契约卡导出**：人物档案可把当前角色导出为本地 JSON 卡片，包含立绘、三技能、特性、关系、疤痕、装备与契约数据。市场「导入卡片」可在新存档重新登记，保留原始数值但不继承退役状态；卡片指纹避免重复导入，数据不完整时拒绝。自定义登记的特性会连定义一起写进卡片，换存档导入不会丢；旧卡片只带特性 id、没带定义时导入照常进行，只跳过认不出的那几条并在提示里说明。导出时还会把**她的故事线**（含已走完的段、当前走到第几幕）一并写进卡片：导入后整份还原到新存档，段号与先后关系重建、`girlId` 指向新登记的少女，指向旧存档的委托与事件 id 会被清掉（该发的委托由故事推进重新发布）；卡片里没有故事线时不动目标存档的现有记录，旧卡行为与以前一致。
- **基地二级菜单**：点击会客厅、诊所、宿舍、星象台打开房间详情，不跳页。会客厅包含议事、成员、物资、势力代表四页；诊所按缺失血量收费并按小时治疗，宿舍负责恢复疲劳；星象台可派两人远行。
- **契约经济**：雇佣有期限，到期需续签；退休金按等级每日计提，退役成员会持续占用事务所预算。欠缴过久会强制退役。月光诊所统一为「治疗」：按缺失血量收费、半小时一档向上取整、按小时线性回血，期间不能派遣、不恢复疲劳（疲劳归宿舍）；「治疗癖好」是独立的 2 小时护理，不回血、单独收费，只提升羁绊并小幅增加侵蚀；重塑、抑制、宿舍都按「一人一格」的卡片展示。记忆重塑与复制契约保留，价格与限制写在按钮上。
- **会客厅与星象台**：基地会客厅可以批准、暂缓或驳回成员议题，也可任命值班助理；每个选项会提前列出星砂、时间、装备、势力态度、安定度或契约者代价，资源不足时锁定并说明还差多少。暂缓只扣提出者羁绊与所属势力态度，并保证下个议事日重新提出；驳回在关系代价之外按主题扣资源。提出者会先播放一段逐句推进的对白，点击「继续」或按空格推进，对白结束后才显示选项。星象台可派两人远行，按小时结算，疲劳过高会自动返程。
- **退休区**：退役成员进入市场页的退休区，可返聘、查看退休金状态，并通过手机远程联络；每次通话消耗星砂，每日首次提升羁绊。
- **代价与纪念**：疤痕降低血量上限并附带精神或肉体后遗症；第五道疤痕导致死亡，角色移入星光纪念墙。累计四道疤痕可申请退役转任文职。
- **CMD 终端**：顶栏 `CMD` 按钮或 `Ctrl+K` 唤起底部终端，支持 `help`、`status`、`advance 30`、`end`、`page base`、`generate`、`preset use <名称>`、`district candy`、`mission <关键词>`、`girl <名字>` 与 `clear`；↑↓ 翻历史，Esc 关闭。终端只是入口，打烊仍然要二次确认。
- **叙事引擎控制台**：连接测试、提案生成、角色起草与每句对话都会记入右下角可折叠、可拖动左上角调整宽高的「叙事引擎」面板（尺寸会记住）。展开一条记录，能看到成功/失败、HTTP 状态与耗时，以及本次实际发出的分段内容（世界观、预设、记忆、历史、玩家输入）、采样参数、模型思维链与 token 用量；可按失败筛选、复制或清空，密钥不会写入日志。输出额度由 设置 → 故事引擎 →「输出预算」统一决定，预设自带的 `openai_max_tokens` 只作参考；常规生成被 `finish_reason: length` 截断时会自动把额度放大一倍（上限 32768）重试一次，仍失败则提示去输出预算里调高该项。
- **对话补全预设**：设置 → 故事引擎 →「对话补全预设」，可导入 SillyTavern 的对话补全预设 JSON（`temp_openai`、`top_p_openai`、`openai_max_tokens`、`main`、`jailbreak` 等），把采样参数与系统提示注入请求；支持 `prompt_order` 顺序、ST 宏、正则脚本（输入/输出、仅提示词/仅显示，带双端预览）、`scenario_format` / `personality_format` / `wi_format` 格式串，以及每个预设自己的接口与密钥（导出带 schema 4 与词条用途、剥除密钥）。词条按用途分成共用、角色对话、每日提案、角色起草、故事线、私人事件、完整剧情、突发事件、服装词条、战斗札记与灯下私语；每个请求只注入共用词条和本任务词条，代码里的 JSON 输出契约永远排在最后。设置页为十一种用途各留一个入口，入口若当前绑定的是只读内置预设，会先复制成可编辑副本并改绑；预设编辑器按任务分十二个标签页（共用、十个生成任务、全部词条），任务页只显示并改绑该任务的预设，共用/全部页保留预设列表与编辑对象下拉，并可改用途、恢复本用途默认；首次升级会把十个任务的默认预设拆成以任务命名的独立副本（如「每日提案」「完整剧情」「战斗札记」），旧「… 副本」默认副本会原地接管改名而不是再复制一份；导入缺少任务词条的 ST 预设时会自动补齐并标记为默认。兼容 SillyTavern 的平铺键名（`temperature` / `top_p` / `max_tokens`）与 `prompt_order` 顺序，导入时会列出被忽略的扩展（SPreset、Tavern Helper、工具调用词条）；十个生成任务（角色对话、每日提案、角色起草、故事线、私人事件、完整剧情、突发事件、服装词条、战斗札记、灯下私语）各自绑定预设，并各有一份以任务命名的可编辑默认预设，旧版三条链路绑定会自动拆开迁移；剧情请求会把 `scenario_format` / `personality_format` 应用到场景与角色性格块，预设词条若未引用 `{{scenario}}` / `{{personality}}`，会自动补一段【场景】【角色性格】；每套预设还能单独填 Endpoint / 模型 / 密钥（三项齐全才生效，导出时剥掉密钥），并支持 ST 的 `regex_scripts`：按 placement 区分输入/输出、按 destination 区分发给模型的 prompt 与界面显示的文本。内置「平衡 / 严格 JSON / 克制语气」三套，也可导出回 ST 格式；预设里的「最大输出」只保留在导入/导出与词条里，真正生效的额度由「输出预算」决定（预设自带的 6000–10000 不会再把手动调低的统一值顶回去）。未支持的字段会在导入报告中列出。旧版设置里的世界观/每日要求会迁移成一份可编辑预设；旧每日要求若还写着「不要给任何数值、奖励或规则」，词条下方会标出冲突并提供一键移除。
- **灯下私语**：自由输入、快捷话题、角色立绘、聊天历史、羁绊和场景记忆面板。配置叙事者后，模型会结合角色完整设定、关系网络、战斗经历、最近参与的委托与全部对话历史，一次生成 1–3 条短消息；台词、动作与表情分开保存，动作以灰色斜体显示在台词下方，左侧立绘跟随当前消息换表情。失败时回退本地剧情。每条输入最多 500 字，每位角色保留最近 60 条消息，日羁绊增长有限制。委托结算后她会不会主动开口，由「世界书 → 数值规则 → 灯下私语」里的六个值决定：胜利基准、失败基准、羁绊加成上限、故事线角色专用档（默认 100%）、概率封顶与每晚上限；正在走故事线的角色优先占用当晚名额，且不吃疲劳与侵蚀修正。
- **议会助手席**：右侧助手席按 1.5 倍尺寸显示值班助理的半身立绘（头到腰的取景，程序化剪影与导入立绘都适用），窄屏时改成「缩略图 + 名字与说明」的横向窄条，不再整块消失。
- **基地**：会客厅、月光诊所、晚安宿舍、星象台平面图；显示在场成员与位置；房间详情、交谈和扩建。扩建宿舍增加契约席位，其他设施扩建提升空间容量。

- **魔女化立绘与人格**：衣柜第五格始终预留「魔女化 · 夜之形」，可提前导入或替换独立立绘、形态描述与六种表情差分，不挤占四格礼装。侵蚀达到 40 后才能切换；切换后普通服装锁定，退出需再点第五格。魔女化期间档案会改用一套由原人格与偏执、多疑、控制欲等负面特质拼成的人格记录，可在状态概览直接编辑；退出后恢复普通人性格，但保留魔女化记录供下次切换。
- **故事蓝图**：详情页的「手动画蓝图」把故事展开成节点图——选项、阶段委托、强制弹窗、议会提案、角色事件、奖励、等待与结束（没有场景节点，旁白写在强制弹窗里）；顶部「资料」可改标题、前提与基调，拖动节点、从端口拖线连到目标节点（Ctrl+C / Ctrl+V 可复制粘贴节点），支持滚轮缩放、右键平移、框选多选、适应窗口、自动整理、试跑与幕概览；阶段委托可直接套用现有委托模板，并分「成功 / 失败」两个出口；强制弹窗可从内容工坊的事件库导入，选中后标题、正文、类型、势力与辖区会同步，运行时按弹窗卡结算，卡被删除则退回手填内容，带选项的弹窗在画布上显示 `o1`/`o2`/`o3` 出口；议会提案只显示「批准 / 驳回」两个出口，暂缓由程序补；奖励可给星砂、特性、属性成长与临时增益，装备只填**阶级 1–5**，具体哪一件由程序按阶级随机发放。保存后随契约卡导出；已有蓝图可「按蓝图开场」，也可以「重新生成」整张替换，编辑不会改动正在进行的剧情。
- **自定义特性与去背景**：自定义登记的特性改为手写（名称 / 描述 / 倾向），内置特性只作为填充模板；「只导入立绘」入口支持一句话画面要求（直接交给叙事者补全档案），入口与立绘步骤都提供按边缘连通的去背景（可调容差、可撤销原图）。
- **全域沉浸式文案与设定重塑 (v41)**：消灭机械干瘪的短句与代码说明书腔调，分五阶段建立具象感官描写与冷调都市怪谈深度的叙事语流——世界书 17 项核心词条与三方势力档案重塑；派遣委托扩充为具备报案背景与感官异象的调查简报；魔物图鉴与天灾 Boss 扩写为详实生态档案与战术对策；58 条技能与 76 件装备重铸施法回路、受击反馈与器物打磨触感；UI 界面说明与羁绊阶段心声全方位升华为所长执业视角与温厚心理描写。全套重塑严格坚守逻辑与数值白名单，全部 409 项状态回归与规则约束测试持续全绿。

## 存档与演示边界

数据保存于当前浏览器、当前站点的 IndexedDB（库名 `night-sugar`，`kv` 表 + `assets` 表）；不再受 localStorage 约 5MB 配额的约束，立绘按原字节保存、不做压缩。刷新可恢复，清除站点数据会丢失；隐私模式/存储不可写时可继续游玩，但无法保证刷新后恢复。导出为 JSON 备份，也可从「设置 → 存档」导入并在二次确认后覆盖当前进度。损坏或关系不一致的本地存档自动回退到初始演示状态。

### 默认本地路径

用 `npm run dev`、`npm run preview` 或 `node scripts/serve.mjs` 起的站点会带一个本地文件通道（`scripts/local-files.mjs`），把默认落点固定在项目内：

- `data/saves/` —— 「设置 → 导出当前存档」直接写进这里；「存档位 → 项目目录里的存档」列的就是这一格的文件，点一下就能读回来。
- `data/cards/` —— 「导出卡片」写进这里；「契约卡库 → 扫描并导入」默认扫的也是这里，不用再手填路径。

两格里的 `.json` 被 `.gitignore` 排除，目录本身（连同 `data/README.md`）留在版本库里。部署成纯静态站点时没有这套接口，程序自动退回浏览器下载与「选择文件夹」，功能不会少，只是落点回到系统下载目录。

初始数据为第 14 日 20:00 开门，内置 7 项基础委托、首批 3 项时段委托（20:00 放号）、4 位在职角色、1 位退役角色、1 位候选角色、4 个房间和一条会客厅议题。夜间会继续在 22:00 与 00:00 各放出一批委托；未完成的紧急委托会过期，长期委托在打烊时统一清场。暂时击退或失败会回到事件池，并保留疤痕与疲劳。可在设置中重置体验。

战斗是确定性规则引擎：同一存档、同一编队、同一时间得到同一结果，模型无法改写战斗数值。每轮行动日志会展开命中与伤害的中间值，战斗结束后可回看完整剧场与战报。

## 故事引擎（可选）

设置 → 故事引擎可连接任意 OpenAI 兼容接口，或 Google Vertex AI，并在浏览器内填写接口地址、模型与密钥。密钥、提示词与自动补充偏好同样存进 IndexedDB，不写入游戏存档；刷新后保留，清除站点数据即删除。

OpenAI 兼容与 Vertex AI 是两份并存的凭证：设置页把两者并排列出，各自填地址/区域、模型与密钥，切到哪一份、哪一份就是「默认接口」，所有生成默认走它，再次打开设置也停在那一份。单个预设可以在「接口与正则」里选「跟随默认 / OpenAI 兼容 / Vertex AI」：选 OpenAI 兼容则自带 Endpoint / 模型 / 密钥三项（三项齐全才生效）；选 Vertex AI 则只填区域、模型与可选的 Express 密钥，凭证沿用设置里那份。因此「每日提案走 Vertex、角色对话走 OpenAI」可以同时成立，没选或没填的预设回落到默认接口。

「输出预算」是唯一决定单次请求 token 上限的地方：先填一个统一值（默认 2048），九个生成任务默认跟随它；重 JSON 的任务另有自己的默认口子（每日提案 6000、故事线蓝图 4000、故事事件/故事线起点/战斗札记 3000），需要时逐项改写，清空输入框即回到跟随统一值，「恢复默认」一键还原。额度给太宽反而容易被思维链和废话占满，所以默认值比预设里的保守；真的截断时会自动放大一倍重试一次。

「接口类型」切到 Vertex AI 后，可以直接把服务账号 JSON 粘进文本框，或用「导入 JSON 文件」读入一份 `.json`：本地用 WebCrypto 现签 RS256 断言，向 `token_uri` 换取 OAuth 访问令牌（有效期内复用，换密钥即失效），再按区域请求 `{location}-aiplatform.googleapis.com` 的 `generateContent`；没有服务账号时，`AIza` 开头的 Express 密钥会走 global 端点。模型名可以只写 `gemini-2.5-pro`，粘 `publishers/google/models/…`、`models/…` 或 `google/…` 也能识别，设置页会实时显示拼好的端点（不含密钥）。请求侧把 system 抽成 `systemInstruction`，多轮 assistant 映射成 `model`，立绘以 `inlineData` 上传；返回的思维链单独进日志，`MAX_TOKENS` 会折算成 `finish_reason: length`，沿用同一套 JSON 截断重试。

Vertex 的 `generateContent` 不接受 OpenAI 的 `presence_penalty` / `frequency_penalty`：部分模型会直接返回 400「Penalty is not enabled for this model」，所以走 Vertex 时这两个参数会被丢弃（预设置里留着也不会影响其它接口）。「测试连接」对 Vertex 会真的发一次极小的 `generateContent`，一次验证密钥、权限、区域与模型名；400 提示模型名或区域不对，403 直接点名需要在 Cloud 控制台启用 Vertex AI API 并授予 `roles/aiplatform.user`，404 提示该模型在所选区域不可用。

「角色起草联网考据」默认关，只在 Vertex 下可用：打开后，自定义登记（立绘导入页或向导第一步）多出「同人角色 / 出处」输入框，填了就先发一次带 `tools: [{ googleSearch: {} }]` 的 `generateContent`，取回摘要与 `groundingMetadata` 里的来源链接，再连同立绘与一句话要求去起草。资料只作为【联网资料（只作考据，可能不准确）】的参考块，排在 JSON 契约之前，立绘与玩家设定永远优先；查不到或接口不支持时照常起草，只在叙事引擎面板留一条「联网考据」记录。网页内容是不可信输入，只影响文案，不能改动游戏状态。

- 「世界观与语气」「本次生成要求」可直接编辑，也可恢复默认。
- 每次连接测试、提案生成、角色起草与对话都会记入右下角可折叠的「叙事引擎」面板。展开条目可看成功/失败、HTTP 状态、耗时、本次读取的分段内容、采样参数、思维链与 token 用量；可按失败筛选、复制或清空；API 密钥不会写入日志。旧的「设置 → 日志」列表已并入该面板。
- 「生成今晚的提案」在本地校验后落地 1 只魔物、1 位候选者、1 条战斗委托、1 条代表委托与 1 份会客厅议题；属性、轮次与奖励由本地规则计算。生成请求会附带当前日期、星砂、安定度、待处理委托、Boss 与三方声望，让新内容接上现有局势。
- 所有模型请求均有 60 秒超时与一次瞬时错误重试；角色对话按 12,000 字符预算（可由绑定预设的 `openai_max_context` 覆盖）裁剪，优先保留系统设定与最近消息，超出部分会明确标注为省略。`4xx` 会直接展示服务端原文，便于判断密钥、模型名或请求格式问题。
- 生成的代表委托会直接挂到对应势力的会客厅代表名下；议题进入待议列表，可批准、暂缓或驳回。
- 自定义契约者在五步向导前提供「只导入立绘」入口：立绘会作为 `image_url` 发送给支持视觉的模型，用于补全身份、外貌与描述；每个字段标注「由使魔补全」并可单独重写，底部可重新生成全部。元素与职阶决定 260 点的自动分配，仍可手动调整；未点「登记并加入名册」前不会写入候选池。不支持视觉的模型会返回明确的接口错误，日志中保留状态码与服务端原文。
- 开启「每日自动补充」后，跨日且满足三池容量预检时自动请求一次，生成中不会重复触发；硬错误不落库，软裁剪会把警告写进通知。

`npm run build` 与 `npm run preview` 走的是 `tools/vite.mjs`：它在能原生跑 TypeScript 的 Node（22.6+）上给 Vite 加 `--configLoader runner`，让配置由 Node 直接加载。默认方式会先用 esbuild 打包 `vite.config.ts`，而 esbuild 解析时会一直向上读目录；在受限账户或沙箱里读到工作区外的目录就会报 `Cannot read directory "../../../..": Access is denied`，构建直接起不来。改走 runner 之后这条路径不再触发，构建与预览都不受影响。

`npm run dev` 还会用 esbuild 预打包依赖（React 的 CJS 入口要走 esbuild 的解析器），所以受限环境里它仍可能撞上同一个报错；这种情况下用 `npm run build && npm run preview`，或在本机普通终端里跑 dev。
