# 夜糖事务所 · 完成度审计与收尾方案

审计基线：`main` / `d31533a`，41 项状态测试、26 组浏览器流程通过，生产构建通过。

这份方案回答的不是“还能加什么”，而是“现在离一个可以长期游玩、可以交给别人维护的版本，还差什么”。结论先说：**核心循环已经成立，但交付稳健性、中后期内容密度和关系/势力叙事仍是明显短板。**

---

## 一、现状判断

| 模块 | 已经成立 | 主要缺口 |
| --- | --- | --- |
| 派遣与战斗 | 七类委托、1–3 人编队、15 分钟轮次、自动战斗、回放、战报、疤痕与死亡 | 战斗事件单一；Boss 只有空月；没有战前/战后叙事选择 |
| 经营 | 星砂、契约期、退休金、市场升级、势力货架、每日货位 | 缺少固定运营支出与中后期回收池；30 日经济曲线未验证 |
| 角色 | 五页档案、七阶关系、特性、侵蚀、魔女化、退役、纪念墙 | 关系基本是数值；没有个人线、同伴冲突、阶段事件 |
| 势力 | 三方声望、货架门槛、代表任务、安定度 | 声望没有等级与晋升；没有势力专属长线 |
| LLM | 日更提案、议程、代表、自定义补全、对话、调用日志、编年史 | 无超时/重试/上下文预算；生成不与编年史和势力状态连续 |
| 内容池 | 三池上限、手动删除、每日自动补充 | 生成内容仍以“一条委托”为主；没有事件链与结局 |
| 存档 | 自动保存、导出、v1 迁移、坏档回退 | 没有导入；导出下载在部分浏览器可能不触发；配额未处理 |
| 表现 | 黑粉视觉、剪影立绘、城市地图、响应式 | 立绘仍是剪影；微排版偏小；无音频；首屏包体偏大 |

## 二、P0：交付稳健性（必须先做）

目标：让“存档、模型、异常、可读性”四件事不再靠运气。预计 4–6 人日。

### P0-1 存档导入与下载修复

现状：`src/App.tsx` 的 `exportSave` 创建 `<a>` 后直接 `click()`，没有挂到 DOM；契约卡已修复同一问题，存档导出尚未。设置页只有导出，没有导入。

方案：

- 抽出 `downloadJson()`，统一挂载/移除 anchor，导出存档与契约卡共用。
- 设置页增加“导入存档”，支持拖入或选择 JSON；导入前展示“第 N 日 / 星砂 / 成员数 / 版本”，二次确认后覆盖当前存档。
- 导入走与 `loadState` 相同的校验；失败保留当前存档并给出具体字段错误。
- 自动保留最近 3 份本地备份（`night-sugar-office:backup:*`），重置或导入前各写一份。

验收：导出文件能在清空 localStorage 后完整恢复；损坏文件被拒绝且当前进度不变；备份可回滚。

### P0-2 存储配额与立绘体积

现状：立绘以 data URL 进入存档，导入 PNG 上限 4 MB；localStorage 通常只有 5 MB，多个导入角色会直接写满。

方案：

- 导入时统一压到 768×960、JPEG/WebP，目标 ≤300 KB；头像从同一张图裁切。
- 写入前计算序列化体积，超过 3.5 MB 时拒绝并提示“删除旧立绘或导出存档”。
- 中期把大对象迁到 IndexedDB，存档只保留引用；迁移需版本号与回退。

验收：连续导入 6 名角色仍可保存；配额失败有明确提示，不静默丢失。

### P0-3 错误边界与生成失败态

现状：没有 `ErrorBoundary`；任何渲染异常会白屏。LLM 失败只靠 toast 与日志。

方案：

- 增加顶层错误边界：保留当前存档、展示“回到派遣 / 导出存档 / 重新加载”。
- 生成按钮增加进行中、失败、空结果三态；失败时保留上次内容，不覆盖。
- 统一 `aria-live` 通知，避免同一条错误弹两次。

验收：人为抛错不白屏；断网生成失败可重试；错误信息包含状态码与服务端原文。

### P0-4 LLM 超时、重试与上下文预算

现状：`chat()` 没有 `AbortController`、超时或 429/5xx 重试；对话一次发送完整 60 条消息 + 5 场战斗 + 完整档案，长局会超出上下文。

方案：

- `AbortController` 60 秒超时；429/500/502/503 重试一次，指数退避。
- 角色上下文按优先级裁剪：当前状态与关系 > 最近 8 条对话 > 战斗摘要 > 更早对话；总字符预算 12,000，超出时保留首尾并标注省略。
- 生成提案同样限制输入，编年史只取最近 20 条摘要。
- 设置页显示本次请求的估算字符数与耗时，不显示密钥。

验收：超时/限流可回退；长局对话不报 400/413；请求体快照测试覆盖裁剪顺序。

### P0-5 生成内容与编年史连续

现状：日更 prompt 只给世界语气与固定要求，不带最近编年史、势力声望、Boss、市场等级；生成内容容易与当前局势脱节。

方案：

- 在 prompt 中注入紧凑“世界状态”：日期、安定度、三势力声望、Boss 是否在场、最近 5 条编年史、当前池占用。
- 生成结果附 `sourcePack`/`chronicleId`，编年史可回链到具体委托或角色。
- 池满时明确告诉模型“只生成缺失类型”，而不是整包拒绝。

验收：连续 7 日自动生成后，新内容能引用前一日事件；池满时只补空缺。

### P0-6 可读性与首屏性能

现状：大量 8–9px 标签；JS 单包约 564 KB，Vite 已警告。

方案：

- 正文与按钮最小 11px，辅助标签最小 10px；对比度按 WCAG AA 复核。
- 路由级 `lazy` 拆分市场、记录、图鉴、自定义向导；城市 SVG 延迟加载。
- 首屏目标：JS ≤400 KB gzip，LCP ≤2.5s（本地预览基准）。

验收：320px 下不横向溢出；键盘走查全部主流程；构建无 chunk 警告。

## 三、P1：玩法闭环（决定“能不能长期玩”）

目标：让关系、势力、Boss、经济四套系统从“数值”变成“事件”。预计 10–14 人日。

### P1-1 角色个人线与关系事件

现状：同伴关系只在战斗胜利/失败时 ±2，死亡时 -3；七阶主要是标签。

方案：

- 每名角色 3 个个人节拍：羁绊 40 / 60 / 80 各触发一次，可在会客厅或对话中回看。
- 每个节拍提供两个选择，影响目标、特性、对玩家关系或对某同伴关系；不改变战斗数值上限。
- 增加同伴冲突事件：两名关系低于 30 的角色同队时，战前触发一次调解选择。
- 关系阶段解锁专属快捷话题与一条记忆，不再只是颜色变化。

验收：六名角色至少各有一条可完成个人线；关系变化能在档案中追溯。

### P1-2 势力等级与专属长线

现状：声望只用于货架门槛与折扣；代表任务每天一条。

方案：

- 四档：戒备（0–20）/ 中立（21–50）/ 亲善（51–80）/ 盟约（81–100），每档解锁一件专属物资与一条势力行动。
- 每条势力线 3 步：代表委托 → 势力设施访问 → 终局选择；选择影响结局与另外两方声望。
- 势力声望不再只增不减：接受对立势力任务会扣另一方。

验收：三方各有一条可完成线；声望变化在记录页有来源。

### P1-3 Boss 轮换与城市级后果

现状：只有“空月”，每 3 日重复同一委托与同一文案。

方案：

- 3 个 Boss 模板轮换：空月（安定度）、糖王（市场物价）、镜修女（关系/侵蚀）。
- Boss 在场时给城市一个可见修正，而不是只扣安定度；击败后掉落专属物资或解除修正。
- Boss 战允许 1–3 人，推荐等级随周期上升；失败不直接删档，但留下区域创伤。

验收：连续 3 个 Boss 周期不重复；每个 Boss 有独立战报文案与掉落。

### P1-4 任务前/后的叙事选择

约束：玩家不干预自动战斗，所以选择只发生在战前与战后。

方案：

- 战斗委托增加 1 个战前选择（强攻/调查/谈判），影响敌人初始伤势、奖励或侵蚀。
- 战后增加 1 个处置选择（净化/封存/交给势力），影响势力声望与编年史。
- 选择结果写入战报与编年史，不改变战斗中间结算。

验收：同一委托两种选择产生不同战报与声望；自动战斗仍不可口胡。

### P1-5 固定运营支出与经济曲线

现状：退休金是唯一持续支出；后期星砂仍可能过剩。

方案：

- 每周固定支出：事务所租金 + 每名在职成员薪金 + 每间房间维护，随等级与人数上升。
- 契约签约时收取一次性押金；提前解约不退。
- 用脚本模拟 30 日：三种玩法（高强度派遣/休闲/囤积）下，星砂中位数与破产率落在目标区间。

验收：30 日模拟无单一策略碾压；连续 3 日不派遣会出现可见压力但不会立即破产。

### P1-6 新手引导与目标感

现状：帮助是静态说明；没有首次进入引导。

方案：

- 首次进入 4 步引导：看地图 → 点一名角色 → 编队派遣 → 推进时间看战报；可跳过，状态写入存档。
- 增加“今夜目标”三条动态任务（如完成 1 次战斗、谈一次话、升级市场），完成后给少量星砂与编年史条目。
- 12 个成就 + 3 个结局（稳定之城/势力傀儡/魔女之夜），按安定度、势力与侵蚀判定。

验收：新存档 3 分钟内能完成第一次派遣；结局条件可在记录页查看。

## 四、P2：内容与表现（决定“看起来是否完成”）

预计 12–20 人日，可与 P1 并行。

1. **分层立绘**：按 `PortraitSpec` 接入头发/服装/五官/饰物分层；种子角色 3 套服装 × 6 表情；导入角色支持按服装/表情上传变体，缺失组合禁用。当前剪影仅保留为加载失败回退。
2. **魔物与战斗表现**：Boss 独特剪影、受击/倒下反馈、轮次切换镜头；不做实时操作。
3. **音频**：夜城环境 loop、UI 轻响、战斗提示音，默认关闭并可记忆。
4. **PWA/离线**：manifest、图标、缓存首屏与字体；离线可继续本地玩法。
5. **记录增强**：30 日范围、CSV 导出、编年史搜索、势力声望来源明细。
6. **无障碍**：axe 自动扫描、屏幕阅读器走查、焦点顺序、对比度；现有 reduced-motion 与键盘标签页保留。

## 五、明确不做

- 不做后端、账号、云同步与支付。
- 不做多人或交易。
- 不允许玩家在自动战斗中途改数值或口胡结果。
- 不把 API 密钥放到服务端代理之外的地方；正式部署必须加代理。
- 不追求无限内容；固定内容 + LLM 补充，以可维护为先。

## 七、最先该做的三件事

1. 修存档导出并加导入/备份——这是玩家进度的底线。
2. 给 LLM 请求加超时、重试、上下文预算——这是长局稳定的底线。
3. 做角色个人线与势力等级——这是“经营 + 叙事”从原型变成游戏的关键。

如果只做一件：先做存档。所有内容都可以后补，丢档不能。
