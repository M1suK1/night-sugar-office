## 第一部分：现有代码与机制不合理之处（走查实锤清单）

通过对 `src/` 全部核心规则、战斗、经济与蓝图模块逐行核对，共定位出 **8 项代码/数值实锤不合理** 与 **4 项机制设计断层**：

### 1.1 代码与数值实锤漏洞（P0 必修）

1. **契约欠款（`pensionArrears`）存在 10 倍重复计费 Bug**
   - **出处**：`src/contracts.ts`（第 10–22 行）对比 `src/rules/conditions.ts`（第 116、128 行）。
   - **问题**：`pensionFor(girl)` 定义的是 **每 10 日** 退休金（界面标明 `/ 10 日`，`accruePension` 亦按 `Math.round(pensionFor(girl) / 10)` 每日划拨）；但 `girl.pensionMissed` 按**天**累加，`pensionArrears` 却写成 `girl.pensionMissed * pensionFor(girl)`（漏除以 10）。欠约 7 天会被罚 70 天的钱（Lv.6 角色欠 7 天被收 4,200 星砂而非 420 星砂）。
   - **修正**：统一按日单价 `dailyPensionFor(girl) = Math.max(1, Math.round(pensionFor(girl) / 10))` 计算欠款。

2. **调查委托三大断层：无视装备词条、假概率一刀切、故事蓝图失败口断路**
   - **出处**：`src/rules/investigation.ts`（第 15、46–57 行）、`src/rules/roster.ts`（第 58–83 行）。
   - **问题**：
     1. 第 15 行硬门槛 `Math.max(...squad.map(g => g.stats[mission.requirement]))` 读的是裸面板 `g.stats` 而非 `effectiveStats(g, state)`，导致装备属性、精炼词条、侵蚀修正、城市信赖加成全部失效；
     2. 面板显示 `20%–99%` 成功率，实际结算根本不掷骰（`squadChance >= 50` 且过硬门槛即 100% 必成，49% 即 0% 必败），界面概率失真；
     3. 调查失败只把委托退回 `open`，不调用 `failStoryMission`（对比战斗失败 `src/rules/missionDefeat.ts` 第 43–45 行），导致故事蓝图里默认工作类型为 `investigation` 的阶段委托**永远走不到 `failure` 分支**。
   - **修正**：统一改读 `effectiveStats(g, state)`；采用确定性哈希掷骰（与面板 `squadChance` 真概率一致）并增加「擦边成功（带额外疲劳）」档位；故事委托调查失败时正常触发 `failStoryMission` 走蓝图失败口。

3. **城市「信赖」阶段（安定度 ≥ 75）全员 +2 共鸣在实战与调查中蒸发**
   - **出处**：`src/economy.ts`（第 51–65、82–86、98 行）、`src/combat.ts`（第 116 行）、`src/rules/roster.ts`（第 59、79 行）。
   - **问题**：`effectiveStats(girl, state)` 需要传入 `state` 才会结算 `state.reputation >= 75` 的全属性 `+2`，但 `unitFromGirl`、`effectiveGuard`、`chance`、`squadChance` 全部漏传了 `state`，导致只有角色面板数字好看，进战斗和调查立刻归零。
   - **修正**：为 `simulateBattle` / `unitFromGirl`、`chance`、`squadChance`、`effectiveGuard` 补齐 `state`（或 `reputation`）参数透传。

4. **世界书「数值」页签漏渲染 4 大分组共 34 项可调规则**
   - **出处**：`src/balance.ts`（第 194–258 行）对比 `src/views/WorldbookView.tsx`（第 204 行）。
   - **问题**：`BALANCE_GROUPS` 只列了 4 个组（`运营与诊所 / 灯下私语 / 城市新闻 / 终局`），漏掉了 `BALANCE_FIELDS` 中实际声明的 `基地设施`、`势力代表`、`事务所会议`、`污染与难度` 四个分组，导致 34 项平衡参数在界面中完全不可见。
   - **修正**：将全部 8 个分组纳入 `BALANCE_GROUPS`。

5. **六系套装有 3 套战斗效果与描述不一致 / 漏实现**
   - **出处**：`src/content/sets.ts`（第 18–38 行）对比 `src/combat.ts`（第 580–657 行）。
   - **问题**：
     - **织梦套（`set-dream`）**：描述写「攻击时 35% 几率令目标失衡 1 轮」，代码中完全未实现；且首轮必闪未限制「单体攻击」。
     - **甜晶套（`set-frosting`）**：描述写「受到致命直击**且心防未碎时**免死 1 次」，代码中未校验 `isGuarded(target)`，且漏掉了心防已碎时共情伤害折算血量的致死分支（两头矛盾）。
     - **幽月套（`set-moonlight`）**：描述写「20% 穿透伤害 + 受击令攻击者伤害降低 15%」，实际只是将 `+20` 塞入普通 `damageBonus`（仍受减伤与心防折减），且虚弱挂的是固定 `-15 魔力` 而非造成伤害 `-15%`。
   - **修正**：在 `combat.ts` 补齐织梦套 35% 失衡（`stun` 1 轮）与单体判定、对齐甜晶套免死条件、将幽月套穿透改为无视目标一半护甲/减伤并修正虚弱倍率。

6. **势力战线（`fronts.ts`）自动结算公式严重偏袒防守方**
   - **出处**：`src/fronts.ts`（第 135–178 行）。
   - **问题**：无人插手时 `attackerScore = attackerPower * 1.1 + swing(0..29)`，而 `defenderScore = defenderPower * 1.1 + (total - swing)`。因 `total` 常在 80–160 之间，`total - swing` 高达 51–160，防守方凭空多拿 50~130 分，导致三方混战几乎永远防守方必胜；而玩家介入时（第 174 行）又突变成 `10 - swing`（可为 `-19`），两套公式量纲完全断裂。
   - **修正**：统一双方对称摆动项（`swing` 对 `29 - swing`），让战力与污染真正决定战线胜负。

7. **宿舍满员死锁与退役文案矛盾**
   - **出处**：`src/rules/rosterOps.ts`（第 342、359–362 行）、`src/rules/roster.ts`（第 13–15 行）。
   - **问题**：满员招募提示「或让资深契约者退役」，但 `applyRetire` 硬性限制 `scars.length >= 4` 才可退役，且无主动解约/转预备役入口；宿舍满 6 人且全员健康时，玩家连已覆灭势力的首领（`hireLeader`）或新卡都无法签入。此外 `hireLeader`（第 173 行）甚至**未检查宿舍容量 `seatsTaken >= capacity`**，会导致超编！同时退役文案写「席位仍留在基地、按月领退休金」，与实际「不占床位、按 10 日折算日结」不符。
   - **修正**：`hireLeader` 补齐床位校验；新增「协商解约 / 转入驻外预备名册」动作；修正退役日志文案。

8. **离城结局人称错位 & 故事蓝图强绑在册单人 `Girl`**
   - **出处**：`src/rules/endingOps.ts`（第 23 行写「她带着星砂离开了樱雾市」，所长应为「你」）；`src/rules/storyRun.ts`（第 48–49 行 `state.girls.find` 找不到即 `abandoned`）。
   - **问题**：蓝图执行器强依赖 `story.girlId` 必须在 `state.girls` 中，无法直接运行以「事务所 / 三方首领 / 全城危机」为主体的主线蓝图。

## 第二部分：制定主线剧情 —— 复用故事蓝图模式《缺月之账》

### 2.1 底层复用方案（零另起炉灶，扩展现有 `StoryGraph`）

现有 `StoryGraph`（`start / incident / mission / opinion / event / choice / reward / wait / end` 共 9 类节点）已具备完整的图推进、存档序列化、画布可视化（`StoryGraphDialog`）与交互演出能力。只需做 **3 点轻量解耦** 即可直接承载主线战役：

1. **主线作用域 `Storyline.scope?: 'personal' | 'main'` + `chapter?: number`**：
   - `personal` 保持现状（每位少女最多 3 段个人线）；
   - `main` 代表事务所主线章节：不因单一契约者离队而废弃；节点需要主角锚点时，通过 `mainStoryAnchor(state)` 动态取**当前值班助理（`representativeOf(state)`）→ 名册首位在勤少女**；涉及势力首领的 `event` 节点自动注入 `factionSceneCast(state, faction)`（兼容玩家自定义卡库首领）。
2. **`wait` 节点增加里程碑门控 `gate`（可选）**：
   - 除等待固定天数/分钟外，支持 `gate?: { minDay?: number; bossClears?: number; minReputation?: number; minCompleted?: number }`，在换日与战后自动检查并放行，让主线节奏自然贴合玩家发育进度。
3. **UI 与工坊双复用**：
   - 派遣页右上角 `EndingProgress` 升级为**「主线 · 缺月之账」章节进度卡**（保留「离城」作为支线终局页签），点击可打开**主线星图画布**（复用 `StoryGraphDialog` 只读视图，已走节点点亮、未走分支迷雾化）；
   - 内容工坊可直接导入/编辑主线蓝图 JSON，实现原版主线与玩家自制主线同构。

## 第三部分：目前游戏的不足与系统优化方案

除上述 Bug 修复与主线蓝图外，当前版本在中后期留存、策略深度与交互闭环上还有 **5 项明显短板**，规划优化如下：

1. **Boss 池单调（目前仅 1 只「糖霜王座」无限循环）→ 扩充至 4 只主题多阶段 Boss**
   - 新增 **「停摆司书」（旧钟楼·梦境/月影系，擅长心防打穿与冷却封锁）**、**「沉锚歌姬」（星见川码头·星光/自然系，护盾反伤与潮汐召唤）**、**「缺月蚀核」（终章专属，吞噬增益与多相切换）**，让每 10 天一轮的城市危机真正考验不同套装与属性配队。
2. **星象工坊有进无出（废装备锁死、满 3 词条无法洗练）→ 增加「拆解回收」与「词条重铸」**
   - 在 `ObservatoryWorkshop.tsx` 增加：**分解装备**（返还 50% 对应套装材料 + 基础星砂）与 **词条重铸**（满 3 词条装备可指定重洗其中 1 条，消耗双倍同套材料），并在仓库卡片补齐叠放数量 `×N` 与一键给少女换装入口。
3. **九大辖区缺乏主动经营与材料消耗出口 → 增加轻量「街区灯塔 / 联络站」**
   - 允许在各辖区投入星砂 + 对应系别材料建立/升级事务所联络点（1–3 级）：提供**压低该区每日污染涨幅、降低被拦截率、每夜稳定回流少量共鸣材料**的效果，让地图从静态背景板变成可经营的夜防网络。
4. **战斗 AI 纯随机 & 同伴关系无实战价值 → 增加「3 档战术方针」与「夜巡默契连携」**
   - 出勤编队可选 **「均衡 / 强攻破阵 / 稳守护持」** 三档方针（调整 `pickSkill` 对奥义、治疗、破心防技能的权重）；
   - 当同队两名少女互相 `relationships >= 70` 时激活**【夜巡默契】**：调查协力加成从 `+4` 提升至 `+8`，战斗中一方破防踉跄时另一方自动获得 1 轮先手/护持支援，让「事务所会议养关系」真正反哺实战！
5. **无 API / 离线退路补齐**
   - 为第 2/3 段个人故事线（未配置 API 时生成本地分支蓝图）与首领拜访（`meetLeader` 离线对白卡）补齐本地兜底，确保纯离线玩家也不会在任何按钮上撞墙。

## 第四部分：分批推进节奏建议（Superpowers 批次划分）

为保证每一批变更独立可测、单文件不超行数上限且随时可交付，建议拆分为 **4 个清晰批次**（也可按你的偏好先挑任意一批开干）：

- **Batch B（主线故事蓝图引擎 +《缺月之账》五章落地 · v262）**：解耦 `Storyline.scope = 'main'` 与 `wait.gate`，内置五章主线蓝图数据、新增主线 Boss、升级首页主线进度与星图画布预览、实装三大主线结局。
- **Batch C（工坊闭环与战术/关系联动 · v263）**：星象工坊拆解与词条重铸、编队 3 档战术方针、同伴高关系【夜巡默契】实战与调查连携、离线兜底补全。
- **Batch D（街区联络站 / 或接续已规划的 v184 残酷模式）**：按你倾向优先做标准模式街区深度，或直接开启此前已写好方案的「残酷模式」全域征服线。
