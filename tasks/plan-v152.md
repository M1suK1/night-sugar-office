# 方案 v152 · 原文三格轮转 + 视觉小说两排站位

> v151 把每侧三人压到 31% 宽，立绘变小了。这一版：
> ① 原文模式单侧三人排成「前排左 A / 前排右 B / 后排 C」，每张仍 47% 宽（=双人时的尺寸）；
> ② 悬停后排 C 的台词时，三人整体轮转 **C→B、B→A、A→C**（不是两人互换）；
> ③ 视觉小说舞台改成「三人在前三人在后」，后排说话时与同列前排互换位置。
> 6v 魔物时左右两栏都是我方——`splitBattleCast` 已经这样分，不需要改。

## 一、原文模式

### 站位
```
┌───────────────┐
│       ▮C      │  后排：47% 宽，居中，抬高 6% 舞台高，压暗 .72
│  ▮A       ▮B  │  前排：47% 宽 × 2，贴底
└───────────────┘
   122px  × 2  ← 与双人时完全相同，不缩小
```

- 侧栏宽度保持 18vw，中间正文仍是 837px @1440，**不受影响**。
- 后排只靠三件事区分：`translateY(-6%)`、`opacity .72`、`z-index` 低于前排。
- 单侧 1–2 人：完全维持现状（单人 47%，双人 47%×2）。

### 轮转规则
- 悬停某句台词 → 高亮该说话人；点击 / 滚动的既有选中逻辑不变。
- 说话人在**前排**：只高亮，不动。
- 说话人在**后排 C**：三人轮转一格
  ```
  A（前左） → C（后排）
  B（前右） → A（前左）
  C（后排） → B（前右）      ← 她转到前排
  ```
- 鼠标移出 → **保留当前轮转结果**，不回到默认；下一次悬停后排的人再轮转一格。
- 重置时机：换一场战斗 / 换一份札记 / 在场名单变化（打开另一份弹窗）。
- 过渡 260ms：`transform` 位移 + `rotateY(18deg → 0)`，读作转身走到前面，不做整圈旋转。
- `prefers-reduced-motion`：无过渡，直接换位。

### 数据
- 新纯函数 `rotateSide(order, hoveredId)` → 新的三人顺序（无变化时返回原数组）
  - `['a','b','c'], 'c'` → `['b','c','a']`（A=b、B=c、C=a）
  - `['a','b','c'], 'a' | 'b'` → 原样返回
  - 1–2 人：原样返回，组件按旧布局渲染
  - `hoveredId` 不在这一侧：原样返回
- 组件里每侧保存一份 `order: string[]`（3 人时启用），悬停后排时用 `rotateSide` 更新并保留；
  换战斗 / 换札记 / 名单变化时重置成队序。
- `BattleNoteDialog`：`renderSide` 在 3 人时切三格（绝对定位），台词挂 `onMouseEnter/onMouseLeave`。
- `EventDialog` session 复用同一套（当前最多 3 人，正好走三格）。

## 二、视觉小说舞台

### 站位（4 人以上生效，1–3 人保持单排）
```
┌────────────────────────────────────┐
│      ▮   ▮   ▮        ← 后排，抬高 12% 舞台高，压暗 .72
│   ▮    ▮    ▮         ← 前排，贴底，各占 1/3
│ ┌────────────────────────────────┐ │
│ │  名牌  台词……               ▼ │ │
│ └────────────────────────────────┘ │
└────────────────────────────────────┘
```

- **尺寸不缩**：前后两排都用 88%（= 三人时的原高度），三列均分。
  三张 88% 立绘并排会轻微交叠（约 90px / 对），这是维持原尺寸的必然代价；说话人 z-index 提到最高。
- 后排抬高 `12%` 舞台高（≈90px @770 高），只露出头肩；压暗到 .72。
- 3v3：前排 = 我方 3，后排 = 敌方 3（cast 顺序本来就是我方在前）。

### 换位规则
- 后排某人开口 → 她与**同列前排**互换（前后排位置互换，不是轮转）；换位后保持到这一段结束。
- 前排某人开口 → 不动（已经在前排）。
- 换段（`segment` 变化）→ 站位重置，重新按 cast 顺序分成前排 3 / 后排其余。
- 动画：300ms `translateY` + opacity + z-index；`prefers-reduced-motion` 直接换。

### 数据
- `src/vn/stage.ts` 新增：
  - `stageRows(ids): { front: string[]; back: string[] }`：前 3 人前排，其余后排；≤3 人全部前排。
  - `swapSpeaker(rows, speakerId): { front, back }`：说话人在后排时与同列（`index % 3`）前排互换，否则原样返回。
- `VnReader`：不再用单排 `shownCast` 平铺；按 `stageRows` 渲染两排，
  每段内维护一次换位结果（segment 变化时重置）。
- `vn.css`：`.vn-cast` 两排布局、后排抬高/压暗、换位过渡；1–3 人沿用现有单排档位。

## 三、边界

### EDGE IN
- 原文：单侧 1 / 2 / 3 人；3v3 两侧同时三格；悬停前排 / 后排 / 移出后保留 / 快速划过。
- 悬停 → 移出 → 再次悬停同一个人（此时已在后排）→ 再轮转一格。
- 滚动时指针不动、台词从指针下经过：只在 `pointermove` 之后允许轮转，避免滚动误触发。
- 舞台：3 / 4 / 5 / 6 人；后排连续两人开口；同一段内反复换位；换段重置。
- 窄屏 ≤860：原文侧栏隐藏走头像条；舞台两排在窄屏下收窄抬高量。

### EDGE OUT
- 事件 cast 上限、`StoryPlayerDialog`、立绘比例与裁切。
- 舞台六人做成「3 上 3 下」以外的排法（如弧形、错位台阶）。
- 后排完全转身 / 镜像。

## 六、性能

- 轮转只在 `mouseenter` 触发，不是每帧：一次悬停最多一次 `setState`。
- 影响范围：`BattleNoteDialog` 重渲染一次。台词区最多几十个节点，React 复用同一批 key
  （`lineKey` / `actor.uid`），DOM 不会重建，立绘不会重新解码，图片也不会重新请求。
- 动画是 `transform` + `opacity`，走合成层，不触发布局重排。
- 结论：可以忽略。真要更省，可以把中间札记正文 `useMemo` 起来，但当前规模没必要。
