# 夜糖事务所 · 战斗 / 内容生成 / 关系与永久代价 设计方案

版本：v2（2026-10-24）
状态：**v2 方案已落地为纯前端原型（2026-10-24）；P0–P6 完成，P7 完成图鉴与验收，叙事适配与 LLM 内容工坊保留边界设计。**
相对 v1 的变化：新增「LLM 模板化内容生产」整章；战斗改为完全不可干预；失败代价升级为「疤痕 → 残疾/精神疾病 → 第 5 条疤痕死亡」；魔物先用几何剪影；其余按默认值锁定。

---

## 0. 本版五条硬结论

1. **规则与叙事彻底隔离**。战斗结果只由本地确定性引擎计算，LLM 只能事后讲述，不能改写任何数值、目标、判定或结局。玩家在对话里「口胡」不会影响战果。
2. **内容全部走模板**。技能、事件、魔法少女、魔物、立绘、头像都由 LLM 填充模板，本地校验与渲染；当前六人五委托退居「种子内容包」，只作为离线兜底与风格基准。
3. **战斗完全自动**。玩家只在战前编队；战中只能观战、回放、跳过，没有任何指令入口。
4. **疤痕是真正的代价**。每条疤痕永久降低血量上限，并表现为具体的精神疾病或肉体残疾；第 5 条疤痕直接死亡，角色永久离场。
5. **魔物先做几何剪影**。用参数化多边形 + 轮廓光渲染，不依赖图像模型；后续可无缝替换为 LLM 生成的同规格 SVG。

## 1. 目标与不可动摇的约束

### 1.1 目标

- 委托分为**战斗**与**调查**，地图、编队、结算、记录全链路区分。
- 魔法少女与魔物共用一套数值与技能框架，双方都有血量与共情值。
- 15 分钟一轮的自动回合制战斗，洞察波动决定行动序，随机技能、随机目标、敏捷命中、魔力×倍率结算。
- 关系系统覆盖对玩家与对同伴，七阶：厌恶 / 疏离 / 戒备 / 平常 / 亲近 / 依恋 / 爱意。
- 战后输出可回放的战斗报告；失败输出疤痕、残疾、关系变化，必要时输出死亡与悼念。

### 1.2 约束

| 约束 | 含义 |
| --- | --- |
| 纯前端 | 无业务后端；LLM 调用由宿主代理，前端不持有密钥 |
| 结果不可辩驳 | 战斗由种子驱动的纯函数模拟，报告即事实 |
| 内容可替换 | 所有角色/技能/事件/魔物来自 `ContentPack`，代码不写死任何具体角色 |
| 存档自洽 | 内容包轮换或丢失后，旧存档仍能正确显示角色与历史 |
| 视觉一致 | 黑底、粉/白、猫/糖/星；无 emoji；本地 SVG 与子集字体 |
| 可访问 | 键盘全通、减少动画、对比度达标 |

## 2. LLM 模板化内容生产（核心新增）

### 2.1 为什么不让 LLM 直接产出成品

直接让模型写完整 SVG、写完整角色 JSON、写事件数值，会同时踩四个坑：画风漂移、数值通胀、引用断裂、注入风险。因此采用**三层分离**：

```
┌ 模板层 Template ──────────────────────────────────────────┐
│ 定义槽位、枚举、字数、预算、禁止项。人来写，版本化管理。      │
└───────────────────────┬───────────────────────────────────┘
                        │ 只允许填槽
┌ 生成层 Generator ─────▼───────────────────────────────────┐
│ LLM 填「意图」：原型、元素、技能原语、外观参数、文案。       │
│ 数值由本地分配器按预算计算，不由模型自由发挥。               │
└───────────────────────┬───────────────────────────────────┘
                        │ 结构化 JSON
┌ 校验层 Validator ─────▼───────────────────────────────────┐
│ Schema → 预算 → 引用 → 安全 → 资产；失败带错误码回炉，最多 2 次│
└───────────────────────┬───────────────────────────────────┘
                        │ 原子提交
┌ 渲染层 Renderer ──────▼───────────────────────────────────┐
│ 参数化 SVG 合成：立绘、头像裁切、魔物剪影。不解析模型给的标记。│
└───────────────────────────────────────────────────────────┘
```

关键点：**模型不写 SVG 源码，只写参数**。渲染器只接受数字与枚举，任何模型输出的文本都不会进入标记，从根上消除脚本注入与画风失控。

### 2.2 ContentPack 与数据来源

```ts
interface ContentPack {
  id: string;                 // pack_<hash 前 8 位>
  hash: string;               // 规范化 JSON 的 SHA-256
  schemaVersion: 2;
  promptVersion: string;      // 提示词版本，便于回滚
  source: 'seed' | 'generated';
  createdAt: string;
  palette: { ink: string; rose: string; blush: string; mist: string; frost: string };
  girls: GirlBlueprint[];
  monsters: MonsterTemplate[];
  skills: Skill[];
  events: EventTemplate[];
  notes: string;              // 本包的主题一句话，用于后续扩写
}

interface GirlBlueprint {
  id: string;                 // g_<8位>，种子角色沿用 yue/tang/...
  name: string; codename: string; title: string;
  element: Element; archetype: Archetype;   // 输出/守护/控制/治愈/侦查
  level: number;
  stats: Record<StatKey, number>;           // 由分配器算，校验预算
  skills: [string, string, string];         // basic / signature / ultimate
  appearance: PortraitSpec;                 // 立绘参数，随存档内嵌
  voice: { tone: string; habits: string[]; taboo: string };
  quote: string;
  description: string;
}
```

`PackSource` 接口把「包从哪来」与游戏逻辑解耦：

```ts
interface PackSource {
  load(): Promise<ContentPack>;                 // 先缓存，再内置，最后生成
  generate(brief: PackBrief): Promise<ContentPack>;
  commit(pack: ContentPack): Promise<void>;     // 原子替换
}
```

实现顺序：`IndexedDbSource` → `SeedSource` → `HostGeneratedSource`（未来接宿主 LLM）。当前原型只启用前两个，第三个是接口占位。

### 2.3 生成流水线（分片、可修复、原子）

一次生成整包容易截断且难修，因此按片生成：

| 片 | 产出 | 上限 | 依赖 |
| --- | --- | --- | --- |
| 1. 世界观 brief | 主题、色调偏移、三条禁忌 | 300 字 | 无 |
| 2. 技能 | 12–18 条技能，含原语与倍率 | 2k tokens | brief |
| 3. 魔法少女 | 4–6 人，引用技能 ID | 2.5k | 技能 |
| 4. 魔物 | 5–6 只，引用技能 ID | 2k | 技能 |
| 5. 事件 | 6–10 个委托，引用魔物 ID | 2.5k | 魔物、角色 |
| 6. 外观 | 每个角色的 PortraitSpec | 每角色 200 | 角色 |

流程：

```
brief → 逐片 prompt → JSON → 片级校验 → 失败则带错误路径修复（≤2 次）
      → 全部通过 → 组装 → 全局引用校验 → 预算复核 → 原子提交 → 预渲染缓存
```

任一片最终失败：**整包不提交**，保留旧包，界面内提示「今晚的名单没有通过校验，已沿用上一版」。绝不出现半套内容。

### 2.4 模板与预算

#### 角色预算

```
budget = 260 + level × 10            // Lv3=290，Lv6=320
每项 40–96，总和 = budget ± 6
至少一项 ≥ 82（角色招牌），至少一项 ≤ 60（真实短板）
```

分配器按原型给权重（输出偏魔力、守护偏共情、控制偏洞察、治愈偏共情、侦查偏敏捷），再用种子抖动 ±4，保证同原型不同角色仍有差异。

#### 技能预算

技能由**原语**组合，倍率有上限：

| 原语 | 作用 | 倍率范围 | 目标数 | 冷却 |
| --- | --- | --- | --- | --- |
| 穿刺 | 单体血伤 | 0.9–1.3 | 1 | 0–2 |
| 心蚀 | 单体共情伤 | 0.8–1.2 | 1 | 0–2 |
| 扩散 | 群体血伤 | 0.5–0.8 | 2–3 | 2–4 |
| 低语 | 群体共情伤 | 0.45–0.7 | 2–3 | 2–4 |
| 缝合 | 治疗 | 0.7–1.1 | 1–2 | 2–3 |
| 护幕 | 护盾 | 20–35% | 1–2 | 3 |
| 灼印 | 持续伤害 | 0.12–0.2 /轮 | 1 | 2 |
| 迟滞 | 降敏捷/命中 | 8–12 | 1–2 | 2 |
| 共鸣 | 增伤/增洞察 | 8–15 | 1–2 | 3 |

校验器计算 **EDPR**（每轮期望伤害）：

```
EDPR = magic × power × targets × hitRate/100
参考命中率 = 50（对敏捷 70 的假想敌）
```

| 档位 | EDPR 区间（Lv5 基准） |
| --- | --- |
| 基础 | 45–65 |
| 本职 | 70–100 |
| 奥义 | 110–150，且冷却 ≥ 4 |

超出即拒绝，并提示「奥义期望伤害 182，超出上限 150，请下调倍率或目标数」。

#### 魔物预算

| 档位 | 血 | 共情 | 单项属性 | 技能数 | EDPR |
| --- | --- | --- | --- | --- | --- |
| 碎屑 | 100–140 | 80–110 | ≤ 65 | 2 | 35–50 |
| 游荡 | 160–220 | 130–180 | ≤ 80 | 2–3 | 55–80 |
| 灾厄 | 260–340 | 200–260 | ≤ 92 | 3 | 90–120 |
| 王座 | 380–460 | 320–400 | ≤ 105 | 3–4 | 130–170 |

魔物可以有一项「超模」属性，但必须配一项明显短板，并在图鉴「弱点」里写明，保证可读。

#### 事件预算

奖励**永远由本地公式算，模型不得给数值**：

```
reward = round10((10 × duration + 220) × difficultyMult × workMult)
difficultyMult: 简单 0.8 / 普通 1.0 / 困难 1.25 / 绝望 1.6
workMult: 调查 1.0 / 战斗 1.25（风险溢价）
duration ∈ {30, 45, 60, 90}，必须是 15 的倍数
```

模型只写标题、描述、线索、敌方阵容、需求能力。校验器核对：战斗事件必须有 1–4 只魔物；调查事件必须有 `requirement/target`；奖励按公式重算，忽略模型给的值。

### 2.5 立绘与头像：PortraitSpec + 本地分层渲染

```ts
interface PortraitSpec {
  palette: { hair: string; hairShade: string; eye: string; cloth: string; clothShade: string; accent: string };
  hair: { style: 0–11; length: 'short'|'medium'|'long'; bangs: 0–5; ahoge: boolean; sideLocks: boolean };
  eyes: { shape: 0–5; highlights: 1–3; lash: 0–2 };
  outfit: { silhouette: 0–7; collar: 0–3; sleeve: 0–3; ribbon: 0–4; pattern: 0–4 };
  accessory: { head: 0–9; ear: 0–4; neck: 0–4 };
  expression: 0–5;
  motif: '猫'|'糖'|'星'|'月'|'蝶'|'钟';
  seed: number;
}
```

- 渲染器 `portrait-kit` 提供 12 种发型轮廓、6 种眼型、8 种服装剪影、10 种头饰，全部手绘路径，组合出足够差异。
- **头像不单独生成**：从立绘按 `viewBox` 裁切上半身，圆形遮罩 + 元素色细环。保证立绘与头像永远一致，也省一次生成。
- 现有六人保留手工立绘，作为 `seed` 包资产；生成角色才走 kit。这样不会为了统一而降低已验收画面的质量。
- 渲染只接受参数，输出固定 400×500、透明底、无 `<text>`、无外部引用。角色名由 React 叠在图上，不写进 SVG。

### 2.6 魔物：几何剪影渲染

```ts
interface MonsterSpec {
  bodyPlan: 'moth'|'feline'|'humanoid'|'machine'|'swarm'|'orb';
  scale: 0.8–1.4;
  appendages: 0–6;
  core: '眼'|'心'|'钟'|'糖'|'月';
  palette: { body: string; shade: string; rim: string };
  aura: '静电'|'余烬'|'花瓣'|'故障';
  motif: '猫'|'糖'|'星'|'月'|'蝶'|'钟';
}
```

渲染规则：三层多边形（暗部 / 主体 / 轮廓光）+ 中心核 + 悬浮碎片。没有五官，靠体态与轮廓光传达威胁感；`aura` 用少量 CSS 动画粒子，减少动画时静止。同一 `MonsterSpec` 的不同实例只改色调与缩放，保证「同族可辨认」。

### 2.7 校验、修复与原子提交

错误码固定，便于修复提示与测试：

| 码 | 含义 | 处理 |
| --- | --- | --- |
| `E_SCHEMA` | 字段缺失/类型错 | 带 JSON path 回炉 |
| `E_BUDGET` | 数值超预算 | 给出实际值与上限 |
| `E_REF` | 技能/魔物/角色 ID 悬空 | 列出悬空引用 |
| `E_LENGTH` | 文案超字数 | 给出字数 |
| `E_SAFETY` | 命中禁忌词/风格违规 | 不重试，整片拒绝 |
| `E_ASSET` | 外观参数越界 | 夹取到合法区间 |

修复提示只回传**错误码 + 路径 + 期望**，不回传整包，控制 token。两次修复仍失败即放弃并回退。

### 2.8 缓存、版本与回退

- 内容包存 IndexedDB（`ns-office-content`），含原始 JSON 与渲染缓存；保存时用 `crypto.subtle` 算 SHA-256。
- 存档只记 `packHash` + 每个角色的 `appearance`、`skills` 快照，**不依赖包还在**。包丢了，角色仍能画出来、技能仍能结算。
- 包轮换时旧存档不迁移、不破坏；只是新事件来自新包。
- 渲染结果按 `specHash` 缓存在内存（Map），上限 64 个，超出 LRU 淘汰。

### 2.9 内容安全与文风

系统提示固定约束：

- 全中文；标题 6–14 字，描述 40–120 字；不使用 emoji、颜文字、网络缩略语。
- 魔法少女是成年/近成年角色，禁止性化描写、恋童暗示、制服凝视；关系止于情感与信任。
- 疤痕相关只写**功能影响与感受**，不写自伤方法、不美化痛苦、不写具体医疗操作。
- 不出现真实人物、品牌、政治与宗教指涉；不生成可执行代码、链接、外部资源。
- 语气基准：克制的夜班叙事，短句，少形容词堆叠；允许一点甜，不允许喧闹。

`safeText` 校验：长度、禁用词、emoji 正则、外链正则、重复标点。命中 `E_SAFETY` 直接拒绝该片，不进入修复循环，避免模型被引导着反复试探。

### 2.10 现有内容如何退居 seed 包

- 新建 `src/content/seed-pack.ts`，把现有 6 人、5 委托、4 房间、基础技能迁入。
- 删除 `game.ts` 里的 `characterIds` 白名单与 `/^\/art\/[a-z]+\.svg$/` 立绘正则（当前在 `src/game.ts:159` 与 `:167`），改为「ID 必须存在于当前包或角色内嵌快照」。
- `createInitialState()` 不再硬编码角色，改为 `createInitialState(pack)`；无包时用 seed。
- 这样生成角色、生成立绘、生成事件都能直接进入现有流程，不需要再改状态层。

## 3. 数据模型（GameState v3）

> 因新增内容包、疤痕、死亡、战斗，版本从 v1 升到 v3；v1/v2 存档均可迁移。

```ts
interface Girl {
  ...现有字段;
  spirit: number; maxSpirit: number;
  baseMaxHp: number;                 // 未受疤痕影响的上限
  skills: string[];
  appearance?: PortraitSpec;         // 生成角色内嵌，保证存档自洽
  scars: Scar[];                     // 0–5，第 5 条致命
  relationships: Record<string, number>;
  exp: number;
  retired?: boolean;                 // 4 条疤痕后的止损选择
  dead?: boolean;
  diedAt?: string;
}

interface Scar {
  id: string; name: string;
  kind: 'mental' | 'physical';
  condition: string;                 // 例如「创伤后夜惊」「跛行」
  description: string;               // 具体表现 + 机制，40–80 字
  effect: { kind: 'stat'|'maxSpirit'|'fatigueRecovery'|'hit'|'initiative'; stat?: StatKey; amount: number };
  maxHpLoss: number;                 // 固定为基础上限的 8%
  gainedAt: string; missionId: string;
  fatal?: boolean;
}

interface Memorial {
  girl: Girl;                        // 完整快照，含立绘参数与疤痕
  diedAt: string; cause: string;
  epitaph: string;                   // 由疤痕与最后一战生成
  lastBattleId: string;
}

interface Mission {
  ...现有字段;
  work: 'combat' | 'investigation';
  squad: string[];
  enemyIds?: string[];
  rounds?: number;
  attempts: number;
  worsened?: boolean;
  lastOutcome?: 'victory' | 'repelled' | 'defeat' | 'draw';
  generated?: boolean;
  sourcePack?: string;
}

interface GameState {
  version: 3;
  ...现有字段;
  girls: Girl[]; memorial: Memorial[];
  missions: Mission[]; battles: BattleState[];
  packHash: string;
}
```

`BattleState` 内保存**已解析的技能快照**（名称、倍率、资源、目标数），不依赖内容包仍在，保证回放与报告永久可读。

## 4. 战斗规则

### 4.1 回合与时间

- 1 轮 = 15 游戏分钟；`rounds = max(2, floor(duration / 15))`。
- 每轮结束推进 15 分钟；报告时间戳与日志、折线图严格对齐。
- 自动推进与手动推进都在「到达委托结束时刻」一次性模拟，不阻塞计时器。

### 4.2 开场快照

```
maxSpirit = round(60 + empathy × 0.6 - fatigue × 0.2)
起始 hp = 当前 hp（伤痛延续）
起始 spirit = maxSpirit
洞察波动 = randomInt(0, 20)，每轮重掷
```

疲劳 ≥ 80 禁止派遣；60–79 提示「心神上限下降」。

### 4.3 行动序

```
initiative = insight + roll + buff - debuff
排序：initiative 降序 → agility 降序 → uid 升序
```

### 4.4 技能抽取

- 冷却为 0 的技能中加权随机：基础 55%、本职 30%、奥义 15%。
- 奥义从第 2 轮起可用；释放后冷却 4 轮，本职 2 轮，基础 0。
- 目标：敌方随机无放回抽 `targets` 个；友方优先百分比最低者；自身固定。
- 无可用技能时「调整呼吸」，不产生效果。

### 4.5 命中

```
hitRate = clamp(50 + attacker.agility - defender.agility, 15, 95)
命中 = randomInt(1, 100) <= hitRate
```

逐目标独立判定；群体技能可能部分命中。边界 15–95 是为了让降命中类效果有意义。

### 4.6 伤害与共情

```
基础 = attacker.magic × power × random(0.9, 1.1)
实伤 = max(1, round(基础 × (1 - shield/100)))
```

- `resource: 'hp'` 扣血，`resource: 'spirit'` 扣共情值。
- 治疗按 `magic × power` 回复对应资源，不超上限。
- 任一资源 ≤ 0 → `down`，移出行动序，不死亡；战斗结束后以 1 点资源回基地。

### 4.7 附加效果

| 效果 | 作用 | 数值 | 持续 |
| --- | --- | --- | --- |
| 灼印 dot | 轮开始扣资源 | 魔力 × 0.15 | 2–3 轮 |
| 迟滞 stun | 跳过下次行动 | — | 1 轮 |
| 护幕 shield | 减伤 | 20–35% | 2 轮 |
| 增幅 buff | 魔力/敏捷/洞察 + | 8–15 | 2–3 轮 |
| 破防 debuff | 敏捷/洞察 − | 8–12 | 2 轮 |
| 回响 regen | 轮开始回复 | 魔力 × 0.1 | 2 轮 |

同名效果不叠加，刷新时长取较高值。DOT 在轮开始、行动序计算前结算，可能造成「未行动先倒下」，报告需写明。

### 4.8 结局

| 条件 | 结果 | 收益 | 事件池 |
| --- | --- | --- | --- |
| 魔物全倒 | 胜利 | 100% + 经验 | 归档移除 |
| 轮数耗尽仍有魔物 | 击退 | 80% | 保留，魔物带伤 −20% |
| 全队全倒 | 失败 | 0 | 保留，进入疤痕结算 |
| 同轮双方全灭 | 同归于尽 | 60% | 保留，按击退处理 |

### 4.9 战后结算

**胜利**：金币 100%；经验 `40 + 魔物档位和 × 15`；参战 `bond +4`（MVP +2）；同队关系 +3；疲劳 +`rounds × 6`。
**击退**：金币 80%；经验 30%；`bond +1`；疲劳 +`rounds × 5`；`worsened = true`。
**失败**：无收益；全队 `bond −6`；同队 −2；疲劳 +`rounds × 8`；进入第 7 章疤痕结算。

## 5. 委托分类与编队

| 维度 | 战斗 | 调查 |
| --- | --- | --- |
| 地图标记 | 裂痕 + 呼吸粉光 | 瞳孔 + 冷蓝扫描线 |

| 时长 | 30/45/60/90 | 30–90 |

编队规则：

- 拖入任务点或点击「加入队伍」；满员时替换最早加入者并提示。
- 实时显示总洞察、平均敏捷、预计轮数、危险度（安全/谨慎/危险/绝望）。
- 移动端用抽屉多选，不依赖拖动。
- 校验：队伍非空、人数上限、无人忙碌、战斗 `hp ≥ 25`、`fatigue < 80`。
- 任一成员疤痕 ≥ 4：弹出**阻断式确认**，必须长按 1.2 秒「我仍要派她去」，并显示「下一次失败她可能不会回来」。不可点遮罩关闭。

### 6.1 七阶

| 阶 | 名称 | 分数 | 视觉 | 表现 |
| --- | --- | --- | --- | --- |
| 1 | 厌恶 | 0–9 | 碎星 | 拒绝同行 |

| 3 | 戒备 | 25–39 | 半掩门 | 礼貌保留 |

| 7 | 爱意 | 85–100 | 双生心 | 专属剧情 |

- 对玩家用 `bond`；对同伴用 `relationships[peerId]`，有向独立。
- 增长：对话（每日上限 +6）、共同休息、共同胜利；下降：失败（对玩家 −6、对同伴 −2）、连续 3 日未交谈（−1/日，最低 15）。

- 逝者的同伴关系冻结为「记忆」，关系图节点变空心星，不再变化。
- 与逝者关系 ≥ 亲近的同伴：触发一次哀悼对话，对玩家 `bond −3`（她们需要一个可以责怪的人）。
- 事务所声望 −5；记录页出现永久条目。

## 7. 疤痕、残疾、精神疾病与死亡

### 7.1 疤痕生成

每次战斗失败，全队每人 +1 条疤痕（同队同因，但表现不同）。疤痕表分两类，按角色当前状态与种子抽取，不重复同名：

**精神疾病**

| 名称 | 机制 |
| --- | --- |
| 创伤后夜惊 | 疲劳恢复 −30% |
| 幻听 | 洞察 −3 |
| 失语 | 共情值上限 −10 |
| 解离 | 对玩家关系增长 −50% |
| 强迫性清点 | 命中 −4 |

**肉体残疾**

| 名称 | 机制 |
| --- | --- |
| 跛行 | 敏捷 −3 |
| 陈旧性骨折 | 最大生命额外 −6% |
| 手部震颤 | 魔力 −3 |
| 视力受损 | 命中 −5 |
| 耳鸣 | 洞察 −2 |

每条疤痕统一追加 **最大生命 −8%（按基础上限累计）**，下限为基础值的 40%。描述必须写清功能影响，例如：

> 「创伤后夜惊」——每到整点会惊醒，无法连续休息。疲劳恢复效率降低 30%。
> 「跛行」——左膝在雨天无法完全弯曲。敏捷 −3，长距离移动会慢半拍。

### 7.2 死亡

- 第 5 条疤痕生成时，角色**死亡**，不再获得第 5 条属性的减益；死因由 5 条疤痕组合生成。
- 死亡在**战斗结算之后**发生，不在回合中途移除单位，保证战斗确定性。
- 死亡流程：战斗报告标注「致命伤」→ 悼念页 → 移入 `memorial` → 容量释放 → 委托回池。
- 死亡不可逆，无复活、无读档绕过（存档只存结果）。
- 悼念页展示：去饱和立绘、名字与称号、存活天数、五条疤痕、最后一战数据、一句墓志铭、与她关系最深的同伴留言。

### 7.3 退役（唯一止损）

- 疤痕达到 4 条时，可在人物详情选择「退役」：转为基地文职，保留对话、关系与立绘，永久不可派遣、不可治疗。
- 退役是玩家对抗死亡唯一的手段，也是「继续用她赌一把」与「让她活下去」之间的真实取舍。
- 退役角色占用容量，但不再参与战斗与派遣；关系增长减半。

### 7.4 提示层级

| 疤痕数 | 界面 |
| --- | --- |
| 1–2 | 人物卡角落显示疤痕刻度 |
| 3 | 派遣面板出现黄色提示「她的身体在报警」 |
| 4 | 红色阻断确认 + 详情页「退役」入口 + 名单红框 |
| 5 | 死亡，进入悼念 |

## 9. 叙事接口与防口胡

```ts
interface NarratorPort {
  opening(ctx: BattleContext): Promise<string>;
  round(ctx: RoundContext): Promise<string>;
  report(ctx: ReportContext): Promise<{ headline: string; body: string[] }>;
  epitaph(ctx: MemorialContext): Promise<string>;
  relationshipBeat(ctx: BeatContext): Promise<string>;
}
```

**防口胡的四条硬规则**

1. 叙事层**只读**：输入是已结算的 `BattleState`，输出是字符串；没有任何写状态的返回值。
2. 玩家对话不进入战斗引擎；对话中的「我命令她赢」不会改变任何随机数、目标或结局。
3. 报告里的数字由状态渲染，不由叙事文本提供；叙事可以写「她勉强站稳」，不能写「剩余 12 点血」。
4. 若未来允许 LLM 提出状态变更，必须走**类型化意图**（`Intent`）→ 与玩家操作同一条校验与结算路径，且需要 UI 明确确认；当前版本不开放。

失败回退：LLM 超时/失败 → 本地模板句；不阻塞结算，不改变结果。

**唯一待定：退役机制**

建议保留「4 条疤痕可退役」：转为文职、永久不可派遣，但仍可对话。它让玩家在「让她活下去」与「再赌一次」之间有真实选择，也让死亡是玩家决策的结果，而不是随机惩罚。

已按实现确认：**保留退役**。累计 4 条疤痕后可退役转文职；退役角色不再可派遣，但仍在名册与关系系统中。第 5 条疤痕触发死亡并进入纪念墙。若后续希望更残酷，可在设置层关闭退役入口，而不改战斗结算。
