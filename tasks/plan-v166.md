# 方案 v166 · 设置面板整理

## TASK

把现有设置面板按「偏好 / 所长档案 / 叙事引擎 / 内容 / 存档与数据」重新分栏，把混在一起的设置、生成动作、身份档案和存档操作放回各自的位置。
同时把「事务所档案」并入所长档案页，并把它的内容存成新开局的本地默认值，避免每局重新填。
只整理信息架构与页面结构，不改已有设置项的存储键或已有元素 id。

## 现状问题

- 一般页塞了三类东西：演出偏好、玩家档案、存档动作；一屏很长，找「导出存档」要先滚过整张玩家表单。
- 故事引擎页同时有一次性连接配置、每次生成都要调的预算、提示词入口、游戏行为开关和一个「生成今晚的提案」动作；设置与动作混在一起。
- 「每日自动补充」被放在故事引擎，实际影响的是内容池；「升级手动加点」也在故事引擎，实际是成长规则。
- 「测试连接」在提示词词条之后，离连接配置很远。
- 契约卡库放在存档动作里，但它是内容入口；标题页也需要它，不能藏进仅游戏内可见的数据页。
- 事务所档案目前只存在 GameState 里（`state.office`），新开局会回落到默认文案；玩家每开一局都得重新写背景、理念和目标。
- 内容池页只有三块池子，和生成入口分开，玩家要先知道去哪个页签生成。

## 新结构

五个页签，页签 id 保持不变；新增 profile / data 两个：

| 页签 | id | 内容 |
| --- | --- | --- |
| 偏好 | general | 演出、动态效果、提示音、升级加点 |
| 所长档案 | profile | 事务所档案（背景/理念/目标）、玩家档案、立绘与表情、外貌/性格/背景/关系 |
| 叙事引擎 | llm | 连接凭证、默认接口、反向代理、测试连接、输出预算、提示词词条、提案审查、联网考据 |
| 内容 | pools | 生成今晚的提案、每日自动补充、事件/魔物/市场三块池子 |
| 存档与数据 | data | 本地自动存档状态、导出/导入、存档位、开局编成、重新开始、原型说明 |

标题页（boot）只显示：偏好 / 所长档案 / 叙事引擎。内容与存档页不出现；契约卡库不放进页签，改为设置标题旁的常驻按钮，标题页和游戏内都能点。

### 偏好

分区标题「演出」：

- 剧情演出（视觉小说）
- 减少动态效果
- 叙事者提示音

分区标题「成长」：

- 升级手动加点

「提案本地审查」移去叙事引擎，因为它只影响提案校验。

### 所长档案

一页两段，顺序是「先事务所、再所长」：

1. 分区「事务所档案」：背景、理念、目标三个 textarea，沿用现有长度上限与占位文案。底部一个「保存事务所档案」按钮，保存后同时写入当前存档与本地默认值。对外代表/助理任命仍留在原来的事务所档案弹窗，不搬进设置。
2. 分区「所长档案」：保留现有 player-card 整体，立绘、表情、外貌、性格、背景、关系原样保留；顶部说明会以 {{player}} 注入叙事提示词。

本地默认值的口径：
- 新增 officeProfile 本地存储键（仅存背景/理念/目标，不含密钥与立绘）。
- 新开局 createInitialState 时优先读本地默认值，缺失才用 DEFAULT_OFFICE_PROFILE。
- 在游戏内编辑事务所档案时，同时更新 state.office 与本地默认值；旧存档已经写过的 state.office 不会被覆盖。
- 标题页的设置里也能填这段档案；填完再开始新游戏，第一局就带着它。

### 叙事引擎

从上到下：

1. 引擎简介 + 「对话补全预设」入口
2. 分区「连接」：默认接口选择、服务账号 / OpenAI 配置、反向代理折叠区、测试连接、当前端点提示
3. 分区「写作」：输出预算、提示词词条
4. 分区「生成行为」：提案本地审查、角色起草联网考据
5. 底部保留浏览器直连警告与密钥只存本机的说明

把「测试连接」从页面底部移到连接分区内；llm-result 跟着测试按钮走。
「每日自动补充」移去内容页；「升级手动加点」移去偏好页；「生成今晚的提案」移去内容页。

### 内容

1. 顶部动作条：生成今晚的提案按钮、每日自动补充开关
2. 生成按钮沿用现有 full 条件（池满时禁用并提示先清理）
3. 三块池子原样：事件池 / 魔物池 / 市场池
4. 契约卡库按钮不放这里，放设置标题旁常驻

### 存档与数据

1. 本地自动存档状态（只读）
2. 分区「存档」：导出当前存档、导入存档、存档位、开局编成
3. 分区「危险操作」：重新开始，按钮保持 danger 样式
4. 最底部原型说明（纯前端 / 密钥只存本机）

## 视觉与交互

- 所有现有 id 不动；只新增 settings-tab-profile、settings-tab-data。移动位置的控件保留原 id。
