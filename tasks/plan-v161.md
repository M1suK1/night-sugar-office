# 方案 v161 · 战斗模板按魔物数量与阶级重新定难度

## TASK

现在战斗模板的「低危 / 中危 / 高危 / 绝望」是手写的，经常和里面的魔物对不上：

- 同样是「1 只游荡」，有的在低危、有的在中危、有的在高危
- 同样「1 只灾厄」，中危 / 高危 / 绝望都出现过
- 推荐等级也各写各的（同样是中危，Lv.3 到 Lv.5 都有）

要改成：**难度与推荐等级统一由「魔物数量 + 阶级」算出来**，模板按这个结果重新排列。

## 现行数据里的例子

| 模板 | 编成 | 现在 | 问题 |
| --- | --- | --- | --- |
| c-single-hound | 游荡 ×1 | 低危 | 和下面同编成 |
| c-single-owl | 游荡 ×1 | 中危 | 同编成不同档 |
| c-single-siren | 游荡 ×1 | 高危 | 同编成不同档 |
| c-single-nurse | 灾厄 ×1 | 中危 | 同编成跨三档 |
| c-single-knight | 灾厄 ×1 | 高危 | |
| c-single-herald | 灾厄 ×1 | 绝望 | |

## APPROACH

### 1. 一个确定的评级函数

新模块 `src/missionTier.ts`：

```ts
const RANK_WEIGHT = { 碎屑: 1, 游荡: 2, 灾厄: 4, 王座: 7 };
// 总分 = Σ 每只魔物的阶级权重
// 低危 ≤2 / 中危 3–5 / 高危 6–9 / 绝望 ≥10
```

示例：

| 编成 | 分数 | 档位 |
| --- | --- | --- |
| 碎屑 ×1 | 1 | 低危 |
| 游荡 ×1 | 2 | 低危 |
| 灾厄 ×1 | 4 | 中危 |
| 游荡 ×2 | 4 | 中危 |
| 碎屑 ×2 + 灾厄 ×1 | 6 | 高危 |
| 游荡 ×3 | 6 | 高危 |
| 王座 ×1 | 7 | 高危 |
| 灾厄 ×2 + 游荡 ×1 | 10 | 绝望 |
| 杂兵 ×6 | ≥10 | 绝望 |

用现有 76 条战斗模板算一遍，分布会变成 **低危 16 / 中危 22 / 高危 23 / 绝望 15**（现在大致是 8 / 45 / 75 / 18）。

### 2. 推荐等级跟着档位走

复用 `suggestedLevel(difficulty, count)`（低危 2 / 中危 3 / 高危 5 / 绝望 7，每多一只 +1，最多 +2），不再手写。

### 3. 在哪里生效

1. **静态模板**：跑一次脚本，把 `missions-combat-low.ts` / `missions-combat-high.ts` 里的 `difficulty` 与 `recommendedLevel` 按新公式重写，并按分数重排条目（低 → 高）。
2. **运行时**：`rules/missions.ts` 的 `makeCommission` 在生成委托时，用实际生成的 `enemyIds` 反推档位与推荐等级，而不是信模板手写的值；LLM/蓝图生成的战斗委托也走同一函数。
3. **工坊**：改魔物编成时自动重算难度与推荐等级；难度输入改成只读展示（或可手动覆盖但标「与编成不符」）。
4. **界面**：委托详情 / 地图图钉上补一行编成摘要，例如 `3 只 · 碎屑×2 灾厄×1`，让玩家看得出为什么是这个难度。

### 4. 老存档与缩放委托

- 读档时对 `work === 'combat'` 的委托重算基线档位；
- 已经被污染抬过档的（`scaledFrom` 有值）：重算模板基线，保留「实际档位 = max(基线, 原实际档)」，说明行照旧显示「模板基线 X」。

## EDGE IN

- 1–6 只、四种阶级、混合编成。
- 同分不同编成（游荡×4 与 灾厄×2 都是 8 → 高危）按同档处理。
- 重复 id 的模板（extra 与 low/high 有重叠）只算一次。
- 工坊改编成 1 只 / 6 只即时重算。

## EDGE OUT

- 不改报酬、时长、目标值的公式；难度变了之后 `DIFFICULTY_SCALE` 造成的间接变化照旧。
- 不重排调查类委托。
- 不新增难度档位（仍是四档）。

## 需要确认

1. **权重与阈值**：`碎屑 1 / 游荡 2 / 灾厄 4 / 王座 7`，`≤2 / 3–5 / 6–9 / ≥10`。这个表会把不少中危移到低危（单只游荡）——如果你觉得单只游荡仍该算中危，我把低危阈值收到 1。
2. **三张没有 `enemyIds` 的老战斗模板**（`canteen-fog`、`shutter-song`、`tooth-collector`）：只写了 `enemyCount`。是保留原难度不参与重排，还是按 `enemyCount` 只数、按游荡估？
3. **模板文件要不要重排顺序**（低危在前），还是只改字段、顺序不动？
